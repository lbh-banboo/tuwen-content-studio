P0 · 组件与资源失效 阻断级：内网／离线 PC 完全不可用

P0-1

图标与字体全量外链 CDN —— 内网／离线 PC 下全站视觉崩塌

19/19 页引用 cdnjs.cloudflare.com + fonts.googleapis.com
837图标实例
实测证据
冷启 Font Awesome CSS 2373 ms ← 单文件 > 2 秒 页面 load 总耗时 3584 ms （FA 占 66%） 字体 CSS（Google） 834 ms 断网（内网）时： .seg-item 视图切换控件 38×29 px → 26×10 px ← 图标盒宽度归零，控件塌陷
根因
  • 无自托管 @font-face、无图标字体子集化、无内联 SVG 兜底
  • theme.css 只声明 --font: "Inter", …，实际字形仍靠外层 <link> 拉取
  • 纯图标型 .seg-item 没有 min-width / aspect-ratio 兜底，图标缺失即塌陷
修复方案
  • Font Awesome 子集化（只保留实际用到的码点）后自托管到 assets/，去掉 cdnjs 引用
  • 或把 837 个 <i class="fa-*"> 编译为内联 SVG symbol sprite
  • Inter 一并自托管 + font-display: swap，回退栈前置 PingFang SC
  • 给 .seg-item / .icon-btn 补 min-width + aspect-ratio: 1，图标缺失也不塌
P0-2

复选框组件三态失效 —— 原生控件溢入设计方块，勾选状态与颜色完全颠倒

.check 存在两套 DOM 形态、三套状态机，互不联动
30处
实测证据 · 形态分裂
形态写法实例页面结果
裸盒 + 注入图标<span class="check"></span>12projects 8 · quality-view 4正常
label + 真实 input<label class="check"><input type=checkbox><span></span></label>22trial-config 8 · delivery 9 · scale-batch 3 · content-feedback 2失效
实测证据 · 原生 input 未被隐藏
.check 盒子 16×16 bg rgba(255,255,255,.05) border rgba(255,255,255,.14) └ input 13×13 appearance: auto opacity: 1 position: static → 系统复选框直接在 16px 设计方块内渲染并溢出
实测证据 · .checked 类零效果 + 点击后状态颠倒
.checked 在 19 个 CSS 文件中 零定义，HTML 中用了 13 处 计算样式对比（trial-config）： .check.checked bg = rgba(255,255,255,0.05) .check:not(.checked) bg = rgba(255,255,255,0.05) ← 完全相同 点击流转： ① 初始 .check.checked native=true isOn=false bg=灰 → 系统勾着，设计系统认为未选 ② 点击后 native=false isOn=true bg=紫 → 紫色框 + 空系统方框 ★ 颜色与勾选状态 完全颠倒
根因
  • .check 原始设计是「裸盒 + app.js 注入 <i>」，勾选靠 .is-on
  • 后续改用 <label> + 真实 input 时，既没写 .check input { position:absolute; opacity:0 }，也没清掉遗留的 .checked 类
  • 结果三套状态机并行：.checked（无样式）、.is-on（真在渲染）、原生 checked（也在渲染）
修复方案
  • 统一为「真实 input + 视觉层」：.check { position: relative } + .check input { position:absolute; inset:0; opacity:0; margin:0; cursor:pointer }
  • 状态改用 .check:has(input:checked) 驱动紫色态，删掉 .checked 类与 bindDemo() 里的 is-on 切换
  • 或保留 JS 方案：初始化时 if (input.checked) c.classList.add('is-on')，并让 change 事件同步 .is-on
  • 12 处裸 span.check 一并改成 <label><input>，彻底消除形态分裂
P0-3

分段控件双 DOM 形态 —— 同视觉组件、不同光标、不同键盘可达性

.seg-item 同时存在 button 版与 span 版
36处
标签分布： <button class="seg-item"> × 20 <span class="seg-item"> × 16 实测 cursor： button 版 cursor = pointer ← 来自 theme.css 的 button{cursor:pointer} span 版 cursor = auto ← .seg-item 自身没写 cursor 键盘可达： button 版 可 Tab 聚焦 span 版 不可聚焦 断网时纯图标态：38×29 → 26×10（见 P0-1）
根因
  • 同一个视觉规格被两种标签实现，样式的「隐式继承」路径不同（button 吃到全局光标，span 吃不到）
  • .seg-item 自身未声明 cursor，也未声明纯图标态的尺寸约束
修复方案
  • 全部统一为 <button type="button">
  • .seg-item 显式补 cursor: pointer，不再依赖全局 button 规则
  • 纯图标态补 min-width: 38px + aspect-ratio: 1

P1 · 交互行为冲突 鼠标／键盘行为在 PC 上互相打架

P1-1

搜索模态 mousemove 抢占键盘选中项 —— 鼠标一抖，键盘选择就没了

app.js:385-391　body.addEventListener('mousemove', …)
键盘 ↓ × 4 → 选中 data-i = 4 鼠标移到第 0 项 → 选中被抢成 data-i = 0 判定：hijacked = true 代码无条件改写 sel： body.addEventListener('mousemove', e => { const it = e.target.closest('.cmd-it'); if (it && +it.dataset.i !== sel) { sel = +it.dataset.i; … } });

PC 冲突点：桌面端鼠标常停在结果列表区域，键盘 ↑↓ 导航会被无意义的指针移动随时重置。触屏没有 hover，反而不受影响 —— 这是纯粹的 PC 端回归。

修复方案
  • 加「键盘优先」标志位：任一次 ArrowUp/ArrowDown 或 input 后置 kbMode = true，mousemove 仅在 kbMode === false 时改写选中
  • 把 mousemove 换成 mouseover（只在跨项时触发一次，而非每像素触发）
P1-2

window.resize 无条件关闭全部浮层 —— 拖窗口 / 开 DevTools 就打断阅读

app.js:416　window.addEventListener('resize', closeAll)
打开通知面板 → 视口 1920 → 1918（仅差 2px） 结果：openedBefore = true stillOpenAfterResize = false closes = true

PC 冲突点：拖动窗口边缘、切换停靠式 DevTools、系统 DPI／显示器缩放变化，都会触发 resize。用户正读通知或搜索结果时被强行关闭，且没有任何提示。

修复方案
  • 改为「只重定位、不关闭」：复用已有的 place(p, anchor) 重新定位，锚点仍在视口内就保持打开
  • 若必须关闭，加阈值：仅当宽度变化 > 80px 或锚点离屏时关闭
P1-3

搜索模态无焦点陷阱、关闭后不还焦 —— 键盘用户直接迷失在背景页

#shCmd 有 role=dialog 但无 aria-modal，无 Tab 循环
实测 Tab 序列（模态打开状态，连按 6 次）
DIV.cmd-body [IN-CMD] A.nf-it [BACKGROUND] A.nf-it [BACKGROUND] A.nf-it [BACKGROUND] A.nf-it [BACKGROUND] A.nf-it [BACKGROUND] Esc 关闭后 activeElement → 不回触发按钮

PC 冲突点：纯键盘操作时，Tab 两次之后焦点就跑到了视觉上被遮罩挡住的背景页通知链接上，回车会直接跳转到其他页面。Esc 关闭后焦点落回 body，用户需要重新 Tab 一遍才能回到搜索入口。

修复方案
  • #shCmd 补 aria-modal="true"，打开时给背景容器加 inert（Chrome 102+ 原生支持）
  • Tab / Shift+Tab 在 #shCmd 内循环（记录首尾可聚焦元素，越界即回绕）
  • closeAll() 记录打开时的 opener，关闭后 opener.focus()

P2 · 可达性与命中区 不阻断功能，但明显违反桌面端可用性基线

P2-1

命中区 16×16 —— 低于桌面端 24×24 最小值

.check 独立在 <td> 内时无可扩大区域
31处
label.check / span.check 16×16 px × 30 label.switch 36×20 px × 1 （members）

WCAG 2.2 SC 2.5.8（Target Size Minimum）要求指针目标 ≥ 24×24 CSS px。.check 多数场合孤零零地放在 <td> 正中，四周虽有空隙但不可点击，实际命中区就是 16×16。

修复方案
  • .check { position: relative } + .check::before { content:''; position:absolute; inset:-6px } → 命中区扩到 28×28，视觉不变
  • .switch 高度提到 24px，或同样用伪元素扩边
P2-2

全站零 :focus-visible 自定义样式

theme.css / components.css / index.css 三个文件中「:focus」「outline」零命中
grep -n ":focus\|outline" theme.css components.css index.css → 零命中 现状：完全依赖浏览器默认焦点环 问题：系统底为 --bg #05040a（近黑），macOS Chrome 默认蓝色焦点环对比度低， 叠加 .btn / .nav-item 自身的圆角，焦点环形状与控件不贴合
修复方案
  • 全局加 :focus-visible { outline: 2px solid var(--purple); outline-offset: 2px; border-radius: inherit }
  • 不用 :focus（避免鼠标点击也出环），统一 :focus-visible
P2-3

<label> 语义误用 —— 未关联任何控件

9 处 label 既非控件标签、点击也无行为
9处
label.row × 4 quality-view label.label × 5 report (2) / members (3) 实测：均不含 input/select/textarea，也无 for 属性 → 屏幕阅读器会把相邻说明文字误当作控件标签；鼠标点击无任何反应
修复方案
  • 纯展示型说明文字一律改回 <div class="label"> / <div class="row">
