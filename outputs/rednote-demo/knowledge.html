# 原表述（错 / 不完整） 更正后口径 依据

C2 打标顺序未定义 打标必须按 D6 → D1 → D4 → D2 → D5 顺序执行 —— 先锁溯源再读内容，先定主体再判策略，最后过风险闸。顺序颠倒会导致 D2 策略判定失去主体锚点。 06 §4.2
C3 「五级检索顺序」 动态上下文组装为六步，且第 0 步是权限与合规过滤（必须发生在检索阶段，不能在生成时补救）。原页面缺此步 → 违反约束 X2。 07 §5 / 05 §9 X2
C4 资产 5 状态（草稿/待确认/生效/被替代/已归档） 资产状态与策略状态是两套，不可混用。资产走 5 状态版本模型；策略走六态状态机（观察信号→相关性线索→候选策略→实验中→已验证策略→失效归档），不可跳级。原页面用「待验证/支持/不支持」五种结论状态代替，粒度不足。 07 §7.4 / 09 §13
C5 「预设字段」只写了每类资产 5–7 个核心字段 预设字段是六域 180 字段的完整维度体系（D1 内容 45 / D2 策略 35 / D3 效果 32 / D4 主体 30 / D5 质量风险 25 / D6 采集溯源 15），每字段带 权重（0–10）+ 权重档（T0–T3）+ 可得性。原页面的「核心字段」是展示摘要，不是采集口径。 00 §4 / 01–05
C6 判优用「点赞 >100 = 优质」 必须用平台官方公式：优质 =（CTR≥9% AND 阅读≥200）AND（互动率≥11% OR 种草率≥7% OR 进店率≥2%），窗口固定 3d，阈值为 3C 家电口径。点赞数不是判优指标；且评论数在本批为采集截断值（上限 20），不可用于热度判断。 03 §1 / KP-A01 / KP-A03
C7 回写只有「提出变更 → 人工确认新版本」两段 回写必须三段式：event_log（不可变事件）→ change_proposal（系统建议）→ asset_version（发布新版本）。禁止原地覆盖；高风险资产 A1/A2/A5 必须人工审批。 09 §18 / 07 §4.3
另有 1 处标准内部冲突需老大裁决：KP-D04 要求长尾词内容的评估窗口为 7d/30d，与 D3 固定 3d 窗口冲突 —— 建议按内容方向分设窗口，见下方效果域说明。

两个 Loop 只在「策略证据层」汇合
共同北极星：提升优秀帖子率
