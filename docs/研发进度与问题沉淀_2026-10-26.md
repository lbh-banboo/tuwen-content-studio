### 已确认的事实
- 指标词表有两份**可对账的来源**：`templates/metric_import_field_guide.md` 与校验工具 `tools/m0/wp03_data/validate_import.py`（COUNT/TEXT/FLAG 三组指标、7 个窗口、六态、五种来源）。M4 计划要求导入器与校验工具**同口径、不得各写一套**，所以 WP38 的词表必须从那里派生或对账。

### 需要你决定的 4 个问题

**Q1 阈值标签的判定规则没有依据（最关键）**
- 仓内只有「50/51/100/101 边界」四个数字，**没有任何一份文档说明标签如何由它们决定**：用哪个指标（点赞？互动量？）、`POTENTIAL`/`QUALITY` 各对应哪个区间、50 与 100 是 `≥` 还是 `>`、为什么测 51 和 101。

- **建议**：本包实现「标签引擎」但不内置任何阈值，规则从带版本的配置读取；配置缺失或数值为空一律 `PENDING`。机制可测（缺失不归零、`PENDING` 不被当成 `BELOW_THRESHOLD`），50/51/100/101 用例只能用测试里显式传入的临时阈值，**不能当产品口径**，文档与证据里如实标注。或者你直接给规则原文。

**Q2 `metric_latest` 的采信规则**
- 同一 `observed_at` 多来源冲突时，`SOURCE_PRIORITY` 的优先级顺序没有依据。

## 6. 本会话踩出的教训（下次别再踩）

1. **改一张表的约束后，要 grep 所有断言它的地方，包括 `tools/` 下的证据脚本，不只是 `tests/`。** WP37 迁移改了 `publication_links` 的唯一索引，我只更新了 WP36 的 pytest 用例，漏了 WP36 证据脚本里同一条判据，以及 WP37 脚本里写死的 pytest 条数（149→150），导致第一次复跑 116/118。
2. **改测试文件后，提交前先单独跑 `tools/quality/check_test_db_isolation.py` 与 `check_test_database_target.py`。** 我在 `67a1702` 里让前者在真树上变红，复跑才发现。判据 ⓔ 要求 `monkeypatch.setenv(<隔离变量>, <DSN 字面量>)` 里**字面量直接传**，不认经常量转一手的写法。
3. **「同形」类防线，测试必须比较响应体，不能只比状态码。** 比 message 与 details（把自己的 id 换占位符后逐字相等），并断言别人的 id 不出现。
4. **回填测试这类会写库的测试，`setdefault` 抵挡不住外部把隔离变量设成共享库**，要用 autouse 夹具 `monkeypatch.setenv` 无条件覆盖，且只作用于本文件。
5. **私有库用 `create_all` 建表，缺迁移才有的函数（如 `rednote_reject_mutation`）**，`test_structure_matches_the_models_on_disk` 在这种库上会失败，是环境问题；要在带迁移的库（如 `rednote_test_wp36`）上验证。
6. **不要只信 agent 的「全绿」。** 本会话 agent 报告里的疑点（WP36 的 404 泄露）我独立实测才确认；agent 自己也承认没验证。
7. 修之前先实测，**不要凭读代码推断其它模块也有同样问题**（ISS-225 的范围控制就是这样来的）。
