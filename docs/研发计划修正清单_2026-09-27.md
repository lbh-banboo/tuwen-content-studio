## 3. ③ G1 出口改为"Demo 展示后端数据"（⏳ 待拍板）

**问题**：§8.2 的 G1 出口是
> "登录→建项目→传文件→假供应商任务→进度→历史 端到端通过"

在"33 页原型 + 零 API 调用"的现实下，这条出口**只能用 Postman/curl 演示**——
而 G1 的立法本意是"人能用了"。用 curl 演示等于把出口降级成了接口自测。

**修正建议**：
> **G1（改）**：选定 Demo 中 **至少 4 个页面**（登录 / 项目列表 / 文件上传 / 任务进度）
> 接入后端真实数据，能完成以下演示：
> 用浏览器登录 → 看到自己的项目 → 上传一个文件 → 看到解析任务进度推进。
> **判据**：这 4 个页面里不存在硬编码的假数据（`grep` 不到写死的项目名/任务状态）。

**为什么这是对的**：这一改同时解决三件事 ——
① 让 G1 重新变成"人能用"的出口；② 把 60 个 operation 从"冻结但无人消费"变成"有消费者"；
③ 用最小代价（4 页）验证契约是否真的够用。

## 12. ⑬ WP28 挂起登记（✅ 已执行，2026-10-05）

**问题**：复盘 §3.3 第 4 条（`研发进度复盘_2026-09-29.md`）写着"**WP28 等 WP02 真机结论后再开**"，
但这句话**只存在于复盘里** ——
- 《待定项与问题登记册》**没有对应条目**（最大编号是 OP-182，全是 WP25 的事）；
- 计划 §9 的 W11 行**照旧排着**"WP28 Live 生成与封装"。

后果：任何人按计划开工都会直接做 WP28，而它的输入形状（四条 Live 导入链路的产物字段、
已验证输出格式白名单、封装规格）**全部由 WP02 定义**，WP02 当前 **0 条真机证据** ⇒
本机"实现"只能是把假设硬编码（本项目高频坑）。

**根因**：这是 **ISS-84 / ISS-95 同族**在**排期侧**的现身 ——
**文档声称已排期（或声称有防线），而没有任何条目与机械判据接着**。
"写在复盘里的一句话" ≠ "登记"，它不阻止任何人按计划开工。

**处置（三处，均已执行）**：

| # | 动作 | 落点 |
|---|---|---|
| 1 | 登记 **OP-183**（**H 本机不可验证类**，🔴 P0，OPEN）：WP28 挂起，唯一前置 = **OP-76**，`OP-76 闭合则本条自动可开工，无需另行拍板` | 登记册 §2-H（第 644 行段） |
| 2 | 计划 §9 的 **W11 行 WP28 标 ⛔ `BLOCKED_ON_EXTERNAL`** + 补"解锁条件"块（阻塞性质 / 唯一前置 / 登记位置 / 本轮处置 / 解锁条件） | `outputs/Rednote研发执行计划_V2.0_2026-09-19.md` §9 |
| 3 | 修正清单总表追加本项 **⑬** | 本文 §0 |

**为什么处置成"登记一条 OP"而不是"再补一句注记"**：OP 会进入
`refresh_register_evidence.py` 的五项机械对账（编号连续性 / 看板条数 /
看板优先级 / §1.2 状态分布 / §3.1 责任方 / §3.2 时机分桶），
**一条写错的 OP 会让脚本 FAIL**；而一句写在某文档里的注记**永远不会 FAIL**。
**这就是"登记过"与"提过一句"的区别。**

**与 OP-76 的分工**（避免重复登记）：OP-76 管"真机**能不能**跑通"（技术可行性未知项），
OP-183 管"跑通**之前** WP28 怎么排期"（工作包级挂起）。
二者不是同一事实的两种写法，而是**两类独立事实**（判据纪律第 4 条）。
