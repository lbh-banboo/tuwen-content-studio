## 3. 结论

**研发计划里 32 个工作包没开发，其中 3 个（WP21/22/23）直接卡住 G2，进而卡住 M3~M5 全部 27 个包。**

真正的瓶颈排序：

1. **前端（最大缺口）** —— 0 代码。后端 39 个端点没有消费者，八步闭环一步都演示不了。
2. **WP21/22/23（M2 剩余 3 包）** —— 卡住整条生产链。WP21 还需要 pgvector + embedding 模型（**ADR-15 的 200 万 chunk 阈值校准就在这里**）。
3. **M0 出口（外部输入）** —— Live 真机、企业网络、AQ 通过线、采购。**这条不由开发进度决定**，是排期顺延的唯一来源。

**一句话**：**进度真实位置是"M1 完成 + M2 做了 4/7"，不是 README 里读出来的"已到 M2"。** M3~M5 的 27 个包一行代码都没有，前端 0 代码。
