## 3. 关键设计决定（含"为什么"）

### 3.1 令牌存摘要、OIDC 令牌存密文 —— 两种存法不能统一

| 凭据 | 存法 | 理由 |
|---|---|---|
| 会话令牌 | SHA-256 摘要 | 只需"验证持有者是否匹配"，无需还原。库被只读泄露也无法接管会话 |
| CSRF 密钥 | SHA-256 摘要 | 同上 |
| OIDC 令牌 | Fernet 对称加密 | 业务需在过期前调 IdP（userinfo/refresh），**必须能还原** |

**为什么会话令牌不用 bcrypt/argon2 慢哈希**：慢哈希是为抵抗"弱口令离线暴力破解"。会话令牌是 256 bit 随机值，字典不存在，暴力枚举数学上不可行。慢哈希只会让鉴权热路径每请求多花几十毫秒做无意义计算。

### 3.2 每个请求都查库，不把角色/状态编码进 Cookie

若把状态编码进 Cookie（或 JWT），鉴权变成"纯客户端验证"。那样管理员停用账号后，已登录浏览器在 Cookie 过期前仍可操作 —— "立即失效"退化成"最多 8 小时后失效"。代价是每请求一次主键索引查询，在 30 RPS 规模下可忽略。**用一次廉价查询换即时撤销能力，这个交换是对的。**

### 3.3 停用走双防线

1. `revoke_all_user_sessions`：停用时撤销全部会话（主防线）
2. `current_user` 每次检查 `user.status == ACTIVE`（保险）

测试**刻意只验证第二道**（不撤销会话）—— 否则无法区分是"撤销生效"还是"状态检查生效"。

### 3.4 CSRF 用双提交 + Origin，两道都要

- 只有 Origin：代理可能剥离 Origin 头；同源子域被入侵时失效
- 只有双提交：若存在 XSS，攻击者可先读 `/me` 再伪造请求头

叠加后攻击者需同时突破"跨站"与"读取响应体"两个限制。

**CSRF Cookie 刻意不加 HttpOnly**：双提交要求前端 JS 能读。这不是疏漏 —— 真正的长期凭据（会话令牌）在另一个 HttpOnly Cookie 里。测试 `test_csrf_cookie_is_readable_by_js` 守住这一点，防止有人"善意改错"。

### 3.5 登录流程状态用签名 Cookie 而非服务端存储

骨架期不引入 Redis/临时表。签名 Cookie 同样保证完整性与真实性；一次性由"回调后立即清除"保证，时效由服务端侧 `iat` 校验兜底（不信 Cookie 的 max-age —— 攻击者可手工构造不带过期的 Cookie）。

**校验顺序：先验签，再解析内容。** 反过来会让畸形载荷先进入 JSON 解析器，扩大攻击面。

### 3.6 新用户默认 OPERATOR，绝不"首个登录者自动成为管理员"

那是经典的提权漏洞。角色由管理员在管理中心显式提升（WP09）。

### 3.7 ID Token 不验签 —— **这是已记录的待办，不是被忽略的风险**

**为什么当前可接受**：ID Token 由后端在**直接的** HTTPS 响应里从 IdP 收到（不经浏览器转发），传输信道已由 TLS 保护。这在 OIDC Core §3.1.3.7 的允许范围内。

**但生产必须验签**，理由：
1. 防御配置错误（如误配 token endpoint 指向攻击者可控服务）；
2. 满足企业安全审计要求（多数内网规范要求验签）。

**当前实现的补偿措施**：强制校验 `iss`（签发方）与 `nonce`（防重放）—— 能挡住"令牌来自其他 IdP"与"令牌重放"两类主要攻击，不依赖签名。

见 §6 [待核实] 第 1 项。

### 3.8 授权码交换**不重试**

授权码是一次性的。第一次请求即使"响应丢失"也可能已被 IdP 消费，盲目重试会得到 `invalid_grant`，把"网络抖动"误报成"授权码无效"，反而掩盖真实原因。登录是低频操作，重试收益远小于误判成本。配置项显式写为 0。

## 7. 附录：端到端验证脚本

`evidence/m1/wp08-identity.log` §[6] 使用的脚本（可直接复跑）：

```python
import sys, uuid, json, urllib.request, urllib.error
from datetime import datetime, timedelta, timezone
sys.path.insert(0, 'services/backend/src')

from rednote.platform.configuration import Settings
from rednote.platform.database import session_scope
from rednote.platform.tokens import generate_session_token, generate_csrf_secret, hash_token
from rednote.modules.identity.repository import IdentityRepository

S = Settings(database_url='postgresql+psycopg://rednote@localhost:5432/postgres',
             environment='test', oidc_issuer='https://idp.test.invalid/realms/rednote',
             oidc_token_encryption_key='dGVzdC1rZXktMzItYnl0ZXMtZm9yLXVuaXQtdGVzdHM=')

sub = f'e2e-{uuid.uuid4().hex[:10]}'
with session_scope(S) as s:
    r = IdentityRepository(s)
    u = r.create_user(issuer=S.oidc_issuer, subject=sub, display_name='端到端用户', role='OPERATOR')
    tok = generate_session_token(); csrf = generate_csrf_secret()
    r.create_session(user_id=u.id, token_hash=hash_token(tok), csrf_secret_hash=hash_token(csrf),
                     expires_at=datetime.now(timezone.utc) + timedelta(seconds=3600))
    uid = u.id

BASE = 'http://127.0.0.1:8899/api/v1'

def call(path, method='GET', cookies=None):
    req = urllib.request.Request(BASE + path, method=method)
    if cookies:
        req.add_header('Cookie', cookies)
    try:
        with urllib.request.urlopen(req, timeout=8) as resp:
            return resp.status, resp.read().decode()
    except urllib.error.HTTPError as e:
        return e.code, e.read().decode()

ck = f'rednote_session={tok}; rednote_csrf={csrf}'
st, body = call('/me', cookies=ck)                       # 期望 200
with session_scope(S) as s:
    IdentityRepository(s).disable_user(uid)
st2, body2 = call('/me', cookies=ck)                     # 期望 401 user_disabled
```

**运行前置**：服务需以 `REDNOTE_OIDC_TOKEN_ENCRYPTION_KEY` 与 `REDNOTE_OIDC_ISSUER` 启动（见 `M1后端骨架说明.md` §2.2 的启动命令）。
