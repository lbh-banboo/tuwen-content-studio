## 3. 关键一致性规则（规格源 02 §277，已摘出原文）

> 锁定 `knowledge_asset`；校验新版本来源、范围、字段完整性；插入 `ACTIVATE` 事件，
> 切换 `active_version`，写索引 Outbox。索引尚未完成时知识状态显示"已生效／索引处理中"，
> **重要事实可以从数据库精确获取；不能因索引延迟读取错误旧事实**。

**这段话直接决定了本包的三个设计点**：

1. **发布是一个事务**：锁 asset → 校验 → 插 publication 事件 → 切换 `active_version` → 写 Outbox。
   （前四项在本包；**Outbox 的写索引事件**按规格也在这里，复用 WP13 的 outbox）
2. **"索引处理中"是一个可显示的状态**，不是错误 —— 需要状态投影（见 §4 的 `projection.py`）
3. **"不能因索引延迟读取错误旧事实"** → **精确读取路径不经过索引**，
   走 `knowledge_assets(product_id, category, active_version_id)`（规格源 §287 明写这是本包的索引）

**索引 Outbox**：规格源 §287 还列了本包应建的精确读取索引：
`knowledge_assets(product_id, category, active_version_id)`。

## 9. 必须遵守的铁律（本项目已踩过，详情见 `rednote-workpackage-delivery` 技能）

- **`entity_type` 用 `KNOWLEDGE`**（受控取值已按包划分：`BRIEF`=WP18 / `KNOWLEDGE`=WP20 /
  `BASELINE`=WP22 / `PROMPT`=WP23）。不要用别的值。
- **`CREATE TRIGGER` 不是幂等的**（重复执行报 `DuplicateObject`）。测试夹具建触发器用
  **幂等四步**：`DROP TRIGGER IF EXISTS` → `CREATE OR REPLACE FUNCTION` → `CREATE TRIGGER`。
  （`CREATE TABLE` / `CREATE OR REPLACE FUNCTION` / `DROP ... IF EXISTS` 本身幂等。）
- **活性验证 > 存在性核对**：只查 `pg_trigger` 只证明存在。必须**试写**
  UPDATE/DELETE/非法 INSERT，断言被拦 + **具体 `sqlstate`**。
- **约束测试必须断言 `sqlstate` 或约束名** —— 只 `pytest.raises(DBAPIError)` 区分不了
  "真的拦住了"与"因为别的原因报错"。（WP18 实测：加了非空列后，试插先撞 23502 而非目标的 23514。）
- **活性验证必须成对**：该拦的拦 + **该过的过**（对照组）。一个永远 `RAISE` 的触发器
  也能让"正向拦、反向拦"两条全绿。
- **反例要按实现的实际判据构造**，不要按字面直觉。先 `pg_get_functiondef()` 看函数体。
- **探针取判定不要用 `commit()`** —— 用 `SET CONSTRAINTS ALL IMMEDIATE`（事务不提交即拿结论），
  最后无条件 `rollback()`。用 `commit()` 取判定 = "把炸弹点着了看它炸不炸"。
  本项目的不可变表**物理删不掉**（WP18 实测连自己的探针残留都删不掉）。
- **零残留判据用"与运行前基线差分"**，不要"全表 0 行"（表里有别的包的合法遗留）。
- **写探针前先查 `information_schema` / `pg_constraint` 实测列名与取值域**，
  不要凭印象写（WP18 一次踩中 5 处错列名）。
- **部分索引的 `WHERE` 必须逐条核对**（少了 `WHERE`，唯一约束会静默退化）。
- **裸 SQL 改状态后读回要 `populate_existing=True`**（identity map 是陈旧副本）。
- **JSONB 字面量一律 `cast(:x as jsonb)`**（`text()` 会把 `{"page":1}` 里的 `:1` 当绑定参数）。
- **迁移版本判据用"不早于"**（`alembic_version` 只存 head），不要"恰好等于"。
- **测试对全局资源既要"只读自己的"，也要"不留下会被别人读到的"**。
- **若草案里有循环外键**，必须显式标注拆环顺序，并说明：
  `DEFERRABLE` 管的是**事务提交期**，**管不了 DDL 期的表存在性**。
- **G2 三件事**（若产出迁移草案要提醒）：删 `op.drop_table`（M0 探针表）/
  删 downgrade 里的重建语句 / 补 `from sqlalchemy.dialects import postgresql`。
