## 2. 算法选型：复用现有设施 vs 新增

**实测事实**（读自磁盘）：

- `modules/knowledge` 的向量设施 = `embedding_profiles` + `chunk_embeddings`（pgvector，`Vector()` 无固定维度）。`chunk_embeddings.chunk_id` **FK `knowledge_chunks`**（`embedding_models.py:280`）；embedder 是**可注入对象**，真实模型**未选型**（OP-44），仓内只有 `indexing.DeterministicEmbedder`（字符 n-gram 哈希进 1024 维，定位是"确定性替身"）。
- 内容正文（`content_versions.body`）**没有任何 embedding 落点**；往 `chunk_embeddings` 写内容向量要么违反 FK、要么写 knowledge 模块（接缝冻结 §1.1：他人模块禁改）。
- `pyproject.toml` 依赖里**没有** numpy / jieba / rapidfuzz / simhash / scikit；唯一向量依赖是 `pgvector==0.3.3`。

| 方案 | 做法 | 结论 |
|---|---|---|
| **A 复用 knowledge 的 chunk_embeddings + pgvector 召回** | 把内容当 knowledge 版本入库再检索 | **否决**：FK 与模块归属都不允许；会把"内容"污染成"知识"；真实 embedder 未选型 |
| **B 复用 `DeterministicEmbedder` + 余弦** | 跨模块 import 替身，余弦比较 | **否决**：它是测试替身（哈希碰撞、1024 维压缩），相似度**不可解释**（说不出"哪些片段相同"）；跨模块 import 与 OP-197 的"平级不互 import"精神相悖 |
| **C 新增纯 Python：规范化 → 字符 2-gram 集合 → Jaccard**（**推荐**） | 见 §4 | **零新依赖**；确定性（无哈希种子、无浮点）；整数运算可精确比较阈值；可解释（可回显共享 n-gram 数 / 并集数）；不依赖未选型的模型。代价：只捕捉字面重合，**不捕捉语义改写**（§4.5 如实登记） |
| D 新依赖（rapidfuzz / simhash / jieba / sentence-transformers / numpy） | — | **只写进开放问题 Q-03**；本设计**不改 `pyproject.toml`**（共享文件，接缝冻结 §1.1 第 17 行）。C 方案的接口（`similarity.py` 的纯函数）为将来替换留了口 |
| E PG 扩展 `pg_trgm` | SQL 内 `similarity()` | 需要 `CREATE EXTENSION`（迁移里做），本机是否已装**未核实**；并且相似度逻辑落在 SQL 里，难以做"阳性/阴性对照"纯函数单测。仅 Q-03 备选 |

**结论（一句话）**：新增 `quality/similarity.py`——纯 Python、零依赖的"规范化 + 字符二元组 + Jaccard（整数千分比）"，比较单元由既有切段口径提供；不复用 knowledge 向量设施（落点与 FK 都不适配），语义级相似度（真 embedding）登记为 `algo_version=2` 的后续路径（Q-03）。

> 判据对称：`algo_version`（代码常量，落库快照，与 WP30 `rule_set_version` 同款）使"今天判重、上周没判"能区分"稿子变了"与"算法变了"。

## 3. 范围、比较单元与切段

### 3.1 "一批"是什么

接缝冻结 §2.1 对 WP33 的说法是"这一批有没有重复、整批质量如何"。**D2（2026-10-19）已决策：WP33 以 WP32 的 `batch_items` 作"一批"的范围**（`batches` 由 WP32 建，写本文时磁盘上尚不存在；因此 WP33 实现与迁移排在 WP32 之后，接缝冻结 §4.2 序已是 …→ WP32 → WP33）。设计取：

- `scope_kind='BATCH'`：请求给 `batchId`；成员 = `SELECT content_item_id FROM batch_items WHERE batch_id = :batchId ORDER BY ordinal`（**只读 SQL**，不 import WP32 模块）；批次必须属于该项目，否则 422（同 `QUALITY_CONTENT_NOT_IN_PROJECT` 口径）；成员数 < 2 或 > `MAX_REPORT_ITEMS` 同下；
- `scope_kind='CONTENT_SET'`：请求显式给 `contentIds[]`（2..`MAX_REPORT_ITEMS`），全部必须属于该项目；
- `scope_kind='PROJECT'`：项目内全部 `content_items`（排除 `state` 无版本者，见 §3.3）。
- **`quality_reports.batch_id`（可空，仅 `BATCH` 范围非空）** —— 此前"不预留 `batch_id` 列"的理由是无消费点（ISS-95 形态）；D2 之后 `BATCH` 范围即消费点，故加列，`scope_digest` 取固定前缀 + `batch_id`（同 `PROJECT` 写法）。
- **引用外键还是只读 SQL 关联：选只读 SQL 关联，`batch_id` 为无 FK 的审计指针。** 理由（按本稿既有惯例）：① 本稿对 WP30/31/32 的表一贯"零 FK"，依据是避开 WP30 R8——`quality_reports → batches` 的 FK 会使 `batches` 被他包表引用，改变 WP32 测试夹具 `drop_all`/`create_all` 的 drop/keep 语义（WP32 说明 Q12(c) 已预判"只建部分表的夹具会报 `NoReferencedTableError`"）；② 本稿其余跨包读取（`media_items`）同样是 SQL 读而非 FK；③ 报告是不可变观测，成员已由 `quality_report_items`（FK `content_items`）钉住，丢失 `batches` FK 不损失可追溯性，`batch_id` 只用于"按批次列报告"。代价：`batch_id` 是悬空指针风险，用服务层校验（批次存在且属本项目）+ `scope_kind='BATCH' ⇔ batch_id IS NOT NULL` 的 CHECK 兜；该代价同 WP32 `estimate_refs`"无 FK 的审计指针，代价已登记"。若主线更愿意要 FK，把 DDL 草案 `QUALITY_REPORTS_DDL` 里注释的那条 FK 打开即可，其余设计不变。

规模上限 `MAX_REPORT_ITEMS`（占位 200，Q-04）：超限 **422 拒绝，不抽样**——抽样会产生"约数"却被当精确值读。

## 4. 相似度阈值与口径（缺失不填 0；NULL / 0 / 约数分离）

### 4.1 单对相似度

```
normalize(text) = NFKC → casefold → 删除所有空白/标点/符号类字符（Unicode 类 Z*/P*/S*/C*）
grams(text)     = 规范化串的字符 2-gram 集合；规范化后长度 = 1 时取 1-gram 集合；长度 = 0 → 该篇该维度"文本为空"
sim(a, b)       = floor(1000 * |A ∩ B| / |A ∪ B|)   （整数千分比 0..1000）
```

- 全部整数运算。阈值比较**不用 floor 后的值**，而用交叉相乘：`|A∩B| * 1000 >= pair_threshold * |A∪B|`（与 floor 比较等价，但把"是否取整丢精度"问题消灭在源头）。
- **规范化删符号会抹掉 emoji 差异**——这是有意的（emoji 不是文字重复），但意味着"只差 emoji"的两篇判 1000‰；已登记为已知取舍。
- 规范化是本模块**私有**函数，**不 import** `knowledge.chunking.normalize_text`（那是切块哈希用的规范化，目的不同；平级不互 import）。

### 4.2 维度与"重复度"定义

对每个维度 `d` 和报告内全部"该维度可比"的篇目：

- `compared_item_count` = 该维度文本非空的篇数；`< 2` ⇒ 该维度 **`NOT_COMPUTED(INSUFFICIENT_ITEMS)`**，**不是 0、不是 OK**。
- `flagged_item_count` = 至少与另一篇构成"相似对"（`sim >= pair_threshold`）的篇数；相似对写入 `quality_similarity_pairs`。
- 维度结论 `verdict`：`flagged_item_count * 1000 > alert_threshold * compared_item_count` ⇒ `ALERT`，否则 `OK`（**严格大于**，对应原型"超阈值"字面；边界取舍见 Q-01）。
- `max_similarity_permille`：该维度全部点对的最大值（信息字段，供 UI 展示"最高 71%"）。

> **如实登记的一处不自洽**：原型 `scale-batch.html` 的"开头段重复 71%（超阈值 70%）… 14 条以同型句式开场（50 条批次）"——14/50 = 28%，与"71%"对不上；"正文结构 81% … 32 条"（32/50 = 64%）同样对不上。**原型数字的统计口径无法反推**。本文取"受影响篇数占比"为维度分，另存 `max_similarity_permille` 供展示，**这是自拟口径，须产品拍板（Q-01）**。

### 4.3 维度清单（共 7 个：计算 4 个，显式 NOT_COMPUTED 3 个）

| 维度码 | 原型对应 | MVP | 理由 |

### 4.4 NULL / 0 / 约数 三者分离（本包守则逐条落点）

| 概念 | 在本包的形态 | 数据库保证 |
|---|---|---|
| **NULL = 没算 / 不适用** | `NOT_COMPUTED` 维度的 `compared_item_count` / `flagged_item_count` / 两个阈值 / `max_similarity_permille` / `verdict` **全部 NULL**；`MISSING` 图位的 `actual_ref` 为 NULL | 维度表 CHECK：`status='COMPUTED'` ⇔ 上述各列同时非 NULL ⇔ `not_computed_reason IS NULL`（双向等价式，WP30 R6 同款） |
| **0 = 算了，确实为 0** | `COMPUTED` 且 `flagged_item_count = 0` ⇒ `OK`；"无相似对"即该维度**无 pair 行**，**仅当该维度行 `COMPUTED` 时才可解读为"比过且低于阈值"** | `quality_similarity_pairs` 的触发器要求对应维度行 `COMPUTED` |
| **约数 = 取整/抽样的近似值** | 相似度落库为**整数千分比（floor）**，响应里带 `approximate: true` 标记；**不抽样**（超限直接 422）；占比不落库为浮点，只落分子分母 `flagged/compared`，展示值由读端算 | 表内**无 float/numeric 列** |
| 汇总层 | `ok / alert / not_computed` 三个维度计数**并列**，`outcome ∈ {ALERTED, NO_ALERT}`（刻意不叫 PASSED，避免"3 个维度没算"被读成通过） | 四个计数 CHECK：`ok+alert+not_computed = 7`；`ALERTED` ⇔ `alert>0` |

### 4.5 已知局限（如实登记）

1. 只捕捉**字面**重合；换词改写（语义重复）抓不到。原型自己写"不以机械低相似度作为唯一质量标准"，与之一致，但**不能宣称"已检查重复"**——只能说"已检查字面相似"。
2. 2-gram Jaccard 对**长度悬殊**的两段偏低（并集被长段撑大）；开头/结尾段长度接近，影响小；`BODY` 受影响最大。
3. 阈值无外部依据（Q-01），所有 `ALERT` 都是"相对占位阈值"的提示，**不得作为阻断条件**。

## 5. 质量报告结构与落 REPORT 版本

### 5.1 报告的组成（一份 = 一个 `quality_report_versions` 行 + 5 张子表）

```
quality_reports                    系列身份（项目 × 范围）+ current_version_id 投影
  └ quality_report_versions        一次计算 = 一个不可变版本（id 同时 FK version_nodes.id）
       ├ quality_report_items          逐篇：纳入/排除、钉死的 content_version_id、generation_context_id、baseline_id
       ├ quality_dimension_results     逐维度（7 行）：COMPUTED/NOT_COMPUTED、阈值快照、计数、verdict
       ├ quality_similarity_pairs      命中相似对（仅 COMPUTED 维度、仅 ≥ 相似阈值）
       ├ quality_media_alignments      逐篇逐图位：顺序对位的期望 ref vs 实际 ref
       └ quality_report_artifacts      导出产物（file_objects, PURPOSE_GENERATED）
```

### 5.2 落 REPORT 版本的方式（`ENTITY_TYPE_REPORT`，当前零消费）

照 WP26 `content_items` + `content_versions` 的同款三件套（身份表 + 不可变版本表 + 注册表）：

1. `quality_reports.id` 作 `entity_id`（系列身份）；
2. `register_version(repo, entity_type=ENTITY_TYPE_REPORT, entity_id=report_id, payload=<摘要快照>, project_id=..., created_by=..., revision_no=<显式传 current_revision_no+1>)`——**必须显式传 `revision_no`**（OP-91：`None` 不幂等，重试会写出"摘要相同、修订号不同"的两个版本；接缝冻结 §5.2 对 WP32 的同款要求）；
3. `quality_report_versions.id = 返回的 node_id`（子表 id 同时 FK `version_nodes.id`，**同一事务**插入，FK 延迟）；
4. `payload` = 报告**摘要**（schemaVersion、algoVersion、范围、`inputFingerprint`、各维度计数/阈值/verdict、纳入/排除计数、对位统计、`detailDigest`）。**payload 内不得含时间戳/随机量**（否则同输入重放摘要不同 ⇒ 撞 409 `INVALID_TRANSITION`）；明细行（pairs / alignments）在不可变表里，`detailDigest` = 对按固定键排序的明细行规范化后的 SHA-256，使摘要覆盖明细（Q-11 问是否需要）；
5. 触发器：`trg_version_nodes_report_paired`（注册表侧"REPORT 节点必须配对 `quality_report_versions` 行"，**先判归不归我管、再判配对**，与 `trg_version_nodes_content_paired` 同款并存于 `version_nodes`，`WHEN (NEW.entity_type='REPORT')` 收窄）+ `trg_quality_report_versions_node_consistency`（节点 `entity_type='REPORT'`、`entity_id=report_id`、`revision_no`/`payload_hash` 一致）。

> `link_dependency(parent=报告版本, dependency=各 content_version, purpose="REPORT_INPUT")` 是否写边 ⇒ Q-12（`purpose` 是自由字符串，无取值域 CHECK）。

### 5.3 报告 "当前态"（读时判，不写入）

详情端点返回 `subjectState`（逐篇）：钉死的 `content_version_id` 是否仍等于该篇**当前**版本（用 §3.3 同口径）⇒ `CURRENT | STALE`；汇总 `staleItemCount`。**只标记，不过滤、不自动重算**（读路径写副作用；与 WP30 R5 同款）。成本：N 次 `read_edit_target`（N ≤ 200），仅详情端点付，列表端点不付（列表只给"是否存在 STALE 未核"？不给，避免假精确——列表**不返回** `subjectState`）。

### 5.4 事实一致性 / 自检汇总（原型批次报告里的"事实一致性校验通过"）

纳入报告会引入对 WP30 三表的**跨包入向 FK**（R8：改变 WP30 测试夹具 drop/keep 语义）或无 FK 的悬空指针。**MVP 不纳入**；如要纳入，只能读时 live 汇总（非快照）或经主 agent 同意加 FK（Q-07）。

## 6. 图文一致性检查（顺序对位派图）

权威口径（契约 §4，老大 2026-10-08 拍板）：**第 i 张配第 i 段；段数 < 3 时多余张回落最后一段**，返回恒长 3；"多张落同一段是合法的"；段落为空 ⇒ fail-closed（`PARAGRAPH_REF_UNKNOWN`）。

做法（每篇一组 `quality_media_alignments` 行，每个 `sort_order` 槽位一行；行只对 `INCLUDED` 篇目，以及 `EXCLUDED(EMPTY_BODY)` 且仍有图的篇目（后者只产出 `NOT_EVALUABLE`，使该取值可达；`NO_VERSION` 篇目无对位行）：

1. `expected_refs = media.schemas.assign_paragraph_refs(paragraph_refs_for_body(body))`（经 `quality/media_bridge.py` 转发两个**纯函数**；**本包不复刻对位规则**）；
2. 读 `media_items`（该内容的全部行）按 `sort_order` 对槽位：
   - 槽位无行 ⇒ `MISSING`（`media_item_id`、`actual_ref` 为 NULL）；
   - 期望 ref 算不出（零段，`SchemaViolation.reason=PARAGRAPH_REF_UNKNOWN`）⇒ `NOT_EVALUABLE`（`expected_ref` 为 NULL）——**不编 ref、不判 ALIGNED**；
   - `actual_ref = expected_ref` ⇒ `ALIGNED`；否则 `MISALIGNED`；
3. 与 WP30 `MEDIA_PARAGRAPH_REF_STALE` 的区别：WP30 判"实际 ref ∈ 当前段集合"（**集合成员**，逐篇）；WP33 判"第 i 张是否在期望的第 i 个 ref 上"（**顺序对位**，并按批汇总"几篇失配"）。**两者结论可以不同且都对**（图指向某个真实存在的段，但不是顺序对位该指的那段 ⇒ WP30 通过、WP33 `MISALIGNED`）。
4. **不得断言** ref 唯一或一一对应（契约 §4：多张同段合法）。
5. `media_items.state` 快照存入对位行（`media_state`，NULL ⇔ 无图位），因为 `media_items.state` 可变；**不对 PENDING/FAILED 图单独判 MISALIGNED**（状态问题归 WP30 `MEDIA_ITEM_NOT_READY`）。
6. 张数：`images_per_content()`=3 固定（OP-198 仍 OPEN，原型是 6/4/9 可配）；**对位槽位数取 `len(expected_refs)`，不写死 3**。超出槽位的多余 `media_items` 行 ⇒ 不落对位行，计入报告摘要 `extraMediaCount`（Q-10 问是否要建模）。
7. OP-199（"顺序对位是否长期口径"，🟢 OPEN）未关闭 ⇒ `MISALIGNED` 只作**提示**，不阻断（Q-10）。

## 9. 并发与幂等

`POST ①` 的固定顺序：

```
1  校验范围：contentIds 去重、数量上限；一次 SQL 确认全部属于 projectId（否则 422）
2  身份：INSERT quality_reports ... ON CONFLICT (project_id, scope_digest) DO NOTHING；
   再 SELECT ... FOR UPDATE   ← 同范围的并发生成在此串行；不同范围互不阻塞
3  逐篇 content_bridge.read_edit_target → 钉死 content_version_id（读，不锁 content_items）
4  逐篇读 media_items（只读）
5  计算 input_fingerprint = sha256(canonical[(content_item_id, content_version_id, 媒体 (sort_order, paragraph_ref) 序列)…, algo_version, 全部阈值])
6  若 == 当前版本 input_fingerprint ⇒ 直接返回当前版本（200，created=false），不写任何行
7  纯函数计算维度 / 相似对 / 对位
8  register_version(revision_no = current_revision_no + 1)；同事务插 versions + 5 张子表；flush
9  UPDATE quality_reports SET current_version_id, current_revision_no, lock_version+1 WHERE id AND lock_version = :expected
   ——持有 FOR UPDATE 时 CAS 必成功，保留 CAS 只为与 content/media 投影推进的写法一致，rowcount=0 视为实现缺陷（抛 500，不吞）
10 （可选，Q-12）link_dependency 写边
```

- **幂等判据 = 输入指纹，不是请求幂等键**：同输入重放不新增版本；**输入变了才新增版本**。不引入 `Idempotency-Key` 头（无计费、无外部副作用；`content` 的幂等键服务于"重复计费"，本包不适用）。
- **只与当前版本比较指纹**，不加 `UNIQUE(report_id, input_fingerprint)`：输入 A→B→回到 A 时，应允许产生第 3 个版本（它是新的时间点观测）；加唯一约束会让回退场景 500。
- **锁序**：只锁 `quality_reports` 一行，不锁任何他人表 ⇒ 无死锁面，也不阻塞 WP29 编辑。
- **读不是一致快照**（READ COMMITTED，逐篇读）：每篇钉死自己的版本，报告对"那一刻读到什么"如实记录；跨篇之间不保证同一时刻，**可接受**，因为指纹含各篇版本 id，任何一篇之后变化都会在下次计算产生新版本。
- ⑥产物幂等：先查 `UNIQUE(report_version_id, format)`，不存在才调 `files.service.store_generated_asset`（该函数每次调用都新建 `file_objects` 行，**自身不幂等**，docstring 已写明）；并发两次可能留下一个孤儿 `file_objects`（同一 blob，无引用）——靠 `quality_reports` 同款 `FOR UPDATE` 串行（锁在 `quality_report_versions` 对应的 `quality_reports` 行上）消除；残余孤儿风险登记为已知取舍。
- 计算为**同步**：纯函数 + 约 N 次读；`BODY` 的 `N=200` 约 2 万对集合交并，量级秒级内。不入 `jobs` 队列（入队要新增 `jobs.kind` 取值并改 `modules/jobs/*.py`，共享文件，同 WP30 §1.5）。

### 16.3 算法与阈值占位

* 规范化：NFKC → casefold → 删除 `Z* P* S* C*` 类字符与变体选择符 `U+FE00..FE0F`；字符 2-gram 集合（1 字取 1-gram，空取空集）；Jaccard 整数千分比 `floor(1000*∩/∪)`；相似判定 `∩*1000 >= 阈值*∪`；维度告警 `flagged*1000 > alert*compared`（严格大于）；全程无浮点，库内无 float/numeric 列。
* **阈值是占位，待 OP-228，不是产品口径。** 常量只在 `types.py`：单对 `950‰`、维度告警 `500‰`，`THRESHOLD_BASIS = "PLACEHOLDER_PENDING_OP-228"`。选这两个数的理由：取**明显保守**（近乎逐字雷同才算一对、过半稿子被标记才告警），宁可漏报不误报，使 `ALERT` 不会被读成业务结论；且两数不与原型的 70/75/60/45 重合，一眼可见非业务数。每份报告把使用的阈值**落库快照**（维度行两个阈值列 + payload `thresholdBasis`），测试证明改常量后历史行与历史响应不变；阈值也进输入指纹，改阈值会产生新版本而不是静默沿用旧结论。响应均带 `thresholdBasis` / `thresholdNote`，并标 `approximate: true`。
* 只检查**字面相似**，不能宣称“已检查重复”（稿 §4.5）。
