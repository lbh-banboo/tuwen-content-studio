**并行开发的纪律（本轮反复验证有效）**
- 新包分支（agent）只写自己的模块目录 + 测试 + 说明；**迁移、`env.py`、`main.py`、`openapi.json`、接缝冻结、登记册、证据脚本、`MIN_SCRIPTS`、CI 全是主线串行动作**。
- 每个 agent 用**自己建的私有库**，禁止碰共享库与他人库；**每条 pytest 必须内联 `REDNOTE_TEST_DATABASE_URL=...`**（bash 变量不跨调用；曾有 agent 漏带，测试数据写进共享库）。
- 测试里**不要加「库名须含 xxx」自检**（会让 CI 的 `check_test_residue` 把整套测试跑在 CI 单库上时整体报错）。
- 新模块的迁移流程：`alembic revision --autogenerate` 起草 → 人工补 `from sqlalchemy.dialects import postgresql`（否则 `NameError`）、换文档头、补触发器（`ddl.all_trigger_ddl()`）、降级只删自有函数不碰 `rednote_reject_mutation` → 在一次性库上升降级往返 → `check_migration_model_parity` + `check_migration_roundtrip`。**遇到循环外键要拆环**（WP33 的 `quality_reports` ⇄ `quality_report_versions` 就是例子：先建一方不带回指外键，另一方建完再 `ALTER` 补，降级反序）。
- **不要只信 agent 的「测试全绿」**：agent 通常不跑 `tools/` 下的全局判据，WP34 的判据 F 违规、WP33 的迁移成环都是主线收口才暴露的。agent 报告里的异常也要独立复现后再采信（本轮有一次 agent 报告 `collect_wp24_code_review` 自检失败，独立复现为假）。
- **agent 因网络中断**（`ENOTFOUND`）时，先看磁盘落盘了多少再续跑（SendMessage 续同一个 agent），不要重来。

**本机环境**：macOS（无 `timeout` 命令；`sed -i` 需 `-i ''`）；zsh 不会把变量按空格拆开（用函数）；中文路径下裸 `grep -r --include` 会失败（用 `/usr/bin/grep -rn`）；git status 过滤中文路径要 `-c core.quotepath=false`（见 MEMORY.md）；PG 在 `/opt/homebrew/opt/postgresql@17/bin/`，本机用户 `rednote`，无密码。
