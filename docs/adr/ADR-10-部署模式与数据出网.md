# ADR-10 部署模式与数据出网

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-19 |
| 决策人 | 老大（业务负责人） |
| 影响范围 | 全部模型调用路径（文案/结构化/静态图/Live 动态/embedding）、模型网关、采集适配器、企业出网审批、备份策略、模式 B 演进排期 |

## 背景

D5 明确企业内网现状为"什么都没有"：无 PostgreSQL、无 S3、无 OIDC、无 GPU、无镜像仓库。其中"无 GPU"这一条对 AI 内容系统是决定性的——系统的核心产能来自模型调用，因此第一个架构问题不是"用什么模型"，而是"模型算力从哪里来"。

两条路可选：

1. **模式 A**：应用与数据全部留在内网，仅允许模型网关通过受控白名单出网调用获批的外部模型 API。
2. **模式 B**：完全离线，自采 GPU、部署本地推理（vLLM 为候选），数据零出网。

模式 B 在数据合规上是"最干净"的答案，但它把 GPU 采购、显存与卡数量级选型、本地模型质量验证、推理并发与稳定性全部压进首版关键路径，而这些在当前均为未测量项。首版交付窗口只有 14~18 周，且 Live 图已是首发硬验收。

本 ADR 只解决"模型算力从哪来"，不涉及 ADR-11 的基础设施自建范围。

## 决策

**我们决定采用模式 A 为主：内网应用 + 受控出网调用获批外部模型；模式 B（完全离线）保留为演进目标，不进首版关键路径。**

具体含义：

1. 出口只有两处，且相互独立：**模型网关**（域名白名单）与**隔离采集适配器**（独立白名单）。数据库、AMQP、MinIO、Keycloak 不对用户网段开放，也不出网。
2. 模型网关是全系统唯一的外部模型调用入口。业务代码不得直连供应商；浏览器不持有任何供应商密钥。
3. 出网内容由模型网关记录**摘要 + 版本 + 字段类别**，普通日志不打印正文。
4. 代理商/中转域名须一并列入白名单，禁止依赖"动态解析域名"。
5. 首版不采购 GPU；模式 B 的启动条件是 WP04 给出本地模型的显存与卡数量级实测，并在 G0-17 落成明确结论（量化选型或列为演进项）。

### 出网数据流矩阵

| # | 数据类别 | 触发方 | 去向 | 出网内容边界（最小化） | 是否允许出网 | 留痕要求 |
|---|---|---|---|---|---|---|
| E-1 | TEXT_STRUCTURED（Brief 结构化/文案生成） | 文本 Worker → 模型网关 | 获批文案模型域名 | 任务必要的最小上下文片段，不含知识库全量、不含其他项目数据 | 允许（需项目非 LOCAL_ONLY） | 摘要 + 提示词版本 + 字段类别 + traceId |
| E-2 | STATIC_IMAGE（静态图生成） | 媒体 Worker → 模型网关 | 获批图片模型域名 | 批准的产品参考素材片段 | 允许（同上） | 摘要 + 素材引用 id + 版本 |
| E-3 | LIVE_MOTION（Live 动态生成） | 媒体 Worker → 模型网关 | 获批动态图模型域名 | 批准素材 | 允许（同上） | 摘要 + 素材引用 id + 版本 |
| E-4 | EMBEDDING（向量化） | 索引 Worker | 建议不出网 | —— | **默认不走外呼**；确需外部 embedding 时须单独列入白名单并重新审批 | 同 E-1 |
| E-5 | 知识库全量正文、费用账本、审计日志、版本快照、备份文件 | 任何组件 | —— | —— | **禁止出网** | 网关侧无对应出网通道即视为合规 |
| E-6 | 采集数据（笔记指标/评论） | 隔离采集适配器 | 独立白名单域名 | 仅请求参数，不回传原始内容至外网 | 仅按 WP03 结论启用的渠道 | 适配器独立日志 |

### LOCAL_ONLY 项目禁止自动降级外呼

- 项目级存在 `LOCAL_ONLY` 标记。标记为 `LOCAL_ONLY` 的项目，模型网关**必须在该项目上完全禁用外呼通道**。
- **禁止自动降级**：当本地/内网能力不可用或外呼失败时，网关不得"顺手改走外部模型"。正确行为是让任务进入失败或 `UNKNOWN` 态并暴露给用户，而不是静默换路径。
- 违规判定口径：任何一条 `LOCAL_ONLY` 项目的出网记录 = 该次调用违规，进入安全事件流程；"配置漏了""策略没生效"不作为免责理由。

### 备份方案（与出网边界绑定）

- 备份对象：PostgreSQL 全量/增量、MinIO 对象、Keycloak 配置、Harbor 镜像与 SBOM、网关出网记录。
- 备份路径：内网独立备份介质为主，**不依赖任何云备份服务**（企业内网亦无云可用）。
- 备份数据与 E-5 同类，**一律不出网**。
- 恢复目标沿用系统指标：RPO ≤ 24h、RTO ≤ 8h，由 WP47 恢复演练验证。

## 理由

**选择模式 A 的理由**

1. 内网无 GPU，且 Day 1 不可能具备。模式 B 要求自采 GPU，属于采购 + 选型 + 调优的长周期动作，与 16+2 周排期直接冲突。
2. 本地模型质量未经验证。当前连外部候选模型的质量都尚未盲测（G0-14 未测），再引入"本地模型能否达到同一 AQ 通过线"这一未知，等于把两个未测量项串成关键路径。
3. 采购风险集中：GPU 规格（24~48 GB 级探测）、到货周期、机房电力与散热、信创要求（WP01 N10 待回填）均未确认，任何一项延误都直接顺延排期。
4. 出网范围是可被约束的：只需送出"任务必要的最小上下文片段"，知识库全量、账本、审计、备份全部不出网，合规面可控且有留痕。

**否决的替代方案**

- **仅模式 B（完全离线）**：数据合规最优，但 GPU 采购与本地模型质量验证不进首版关键路径；作为演进目标保留（研发计划 §3.2）。**否决原因**：排期不可承受 + 双重未知项。
- **A/B 并行（首版即双通道）**：需同时维护两套模型适配与两套质量基线，6 FTE 无冗余。**否决原因**：容量不允许，且并行会稀释 Live 与质量两条关键路径。
- **单机容器 + 外部模型直连（最快验证档）**：单点、不可称可用、且供应商密钥暴露面大。**否决原因**：不满足内网与可持续要求（§3.2 已否决）。
- **浏览器直连供应商**：省一层网关，但密钥落到客户端且无统一留痕。**否决原因**：违反最小留痕与密钥不出服务端原则。

## 代价与风险

**代价**

1. Brief 片段出网需企业审批（E3，W2 截止）。审批周期的等待是显式排期占用，不是缓冲。
2. 必须实现并维护模型网关（含白名单、字段类别、摘要留痕、`LOCAL_ONLY` 拦截），工作量已计入 WP16。
3. 质量与成本受供应商约束：供应商不稳定或计费争议会直接传导（风险 R6），需保留第二供应商适配位。
4. 出网即意味着数据离开内网边界，合规上必须靠"最小化 + 留痕 + 禁止清单"三件事守住，而不是靠"相信供应商"。

**重新审视条件**

- N6（出网政策）= 不允许任何出网 → 模式 A 不成立，必须立即升级老大，转评估模式 B，排期与采购同时变更（WP01 §5 判定规则）。
- E3 白名单审批被否决或长期悬置 → 同上。
- G0-17 给出本地模型显存与卡数量级且质量可达 AQ 通过线 → 可在后续版本启动模式 B，本 ADR 相应修订。
- WP04 盲测显示获批外部模型无法达到 AQ 通过线 → 需重新评估模式与试点范围（与 ADR-12 联动）。

## 验证方式

| 判据 | 验证方法 | 证据 |
|---|---|---|
| 出口只有两处 | 网络连通矩阵实测：模型网关与采集适配器之外无出网路径 | WP01 连通矩阵 + WP01-conn-* 记录 |
| 数据面不出网 | 断网启动（G0-20）：PG/MinIO/RabbitMQ 启动过程无外网访问 | 断网启动记录 |
| `LOCAL_ONLY` 不降级 | 集成测试：构造 `LOCAL_ONLY` 项目 + 外呼失败，断言"任务失败但无出网记录" | 异常矩阵项 + 网关日志断言 |
| 出网留痕 | 抽查网关记录：每条含摘要、版本、字段类别、traceId，且不含正文 | 网关记录抽样报告 |
| 备份不出网 | 备份链路流量审计，无外部目的地 | 运维审计记录 |
| 恢复目标 | WP47 恢复演练达 RPO ≤ 24h、RTO ≤ 8h | 恢复演练报告 |
