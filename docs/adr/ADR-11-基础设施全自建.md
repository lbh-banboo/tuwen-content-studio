# ADR-11 基础设施全自建

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-19 |
| 决策人 | 老大（业务负责人） |
| 影响范围 | 运维投入（M0~M1 升全职）、机房与硬件采购、安装顺序、镜像与离线包、备份与监控、后续云化可能性 |

## 背景

D5 的内网现状是"什么都没有"：无 PostgreSQL、无 S3、无 OIDC、无 GPU、无镜像仓库。这意味着没有一项平台能力可以复用，所有底座组件都必须在企业内部从零装起来。

这不是"要不要自建"的选择题，而是"自建的范围与顺序如何定"的问题。但仍需明确决策并留档，因为它带来两个必须被显式承担的后果：

1. **运维量被低估**（风险 R4）：零基础自建的安装、调试、补丁、备份、监控工作量远高于"已有平台，只需部署应用"的情形。
2. **关键路径依赖采购**：服务器未到货前，安装只能在开发机上进行；出网策略未批准前，镜像只能离线导入。

本 ADR 只定"装什么、按什么顺序装、为什么不考虑云"。应用层架构决策见 ADR-01~09，出网边界见 ADR-10。

## 决策

**我们决定在企业内网全自建以下基础设施，并按依赖顺序安装；不使用任何云或托管服务。**

### 组件清单与用途

| # | 组件 | 版本口径 | 用途 | 是否对用户网段开放 | 备注 |
|---|---|---|---|---|---|
| C1 | PostgreSQL 17 + pgvector + pg_trgm | 17 主线 + pgvector 0.8 系列 | 主库：业务数据、状态机、domain_events、版本快照、审计、向量索引 | 否（仅应用网段） | 选 17 主线：扩展与运维工具链验证最充分；18 留作后续独立评估 |
| C2 | RabbitMQ 4.x（quorum queue） | 4.x | 任务队列：消息只传 jobId/schemaVersion/traceId | 否 | 3 节点 quorum；应用服务器 2 节点 + 运维节点 1 节点 |
| C3 | MinIO（S3 兼容） | `[待核实: WP05 当周核官方最新 RELEASE digest]` | 对象存储：研究文件、生成媒体、预览与正式资产分离、交付包 | 否 | S3 兼容子集需验证：分片、版本、生命周期、签名 |
| C4 | Keycloak | 26.x `[待核实: WP08 当周核官方补丁]` | 身份：OIDC Authorization Code + PKCE，令牌留服务端 | 需开放（登录用） | M0 可独立建册，后续对接企业 IdP（E8） |
| C5 | Harbor | 2.x `[待核实: WP05 当周核官方补丁]` | 镜像仓库：离线包、镜像、SBOM 托管 | 仅运维面 | 内网无公网镜像源的前提件 |
| C6 | Prometheus + Grafana + OpenTelemetry | 按实施当周锁定 | 监控与告警：指标、追踪；日志只带 requestId/jobId/contentId | 仅运维面 | —— |
| C7 | 内网备份 | 脚本 + 独立备份介质 | PostgreSQL dump/WAL、MinIO 对象、Keycloak 配置、Harbor 镜像与 SBOM | 否 | 备份不出网（ADR-10 E-5） |
| C8 | 反向代理 / HTTPS 网关 | 内部域名 + 内部 CA | 统一入口，双 API 实例负载 | 是（唯一用户入口） | 依赖 E2（内部域名/DNS/CA） |
| C9 | NTP 时间同步 | 企业提供或自建 | 影响 timestamptz 与签名校验 | 仅内网 | WP01 N8 待回填 |

### 安装顺序依赖

```text
S0 采购到货 / 开发机临时代用（WP00、WP05）
  └─ S1 Harbor（离线包托管前提）
       └─ S2 PostgreSQL 17 + pgvector（一切业务数据的根，先装先验"重启不丢"）
            └─ S3 MinIO（对象存储，与 PG 并行可做，但冒烟校验依赖 PG 元数据）
                 └─ S4 RabbitMQ（quorum 需 ≥3 节点，依赖运维节点就位）
                      └─ S5 Keycloak（依赖内部域名与 CA，E2 到位后）
                           └─ S6 反向代理 + HTTPS + 双 API 实例
                                └─ S7 Prometheus/Grafana/OTel（观测面最后接，不阻塞业务）
                                     └─ S8 备份脚本 + 恢复演练（WP47）
```

关键约束：

- **S1 必须最先**。内网无公网镜像源，没有 Harbor 就无法把镜像带进内网；同时 G0-20 要求"无公网 CDN / 首次启动不下载依赖"。
- **S3 与 S4 可并行**，但 quorum queue 需要 3 节点，节点未到货前只能用单节点做功能验证，**不得把单节点验证结果当作生产可用证据**。
- **S5 依赖内部域名与 CA**（E2，W2 截止）；未到位时可先用 IP + 自签证书做开发验证，但不得作为 M1 网络验收通过依据。
- 安装即 IaC 化，产出 ansible/compose 清单，避免重建环境时重复劳动（WP05 增量）。

### 为什么不用云 / 托管

| 替代方案 | 否决原因 |
|---|---|
| 公有云托管 PG / 对象存储 / 身份服务 | 数据必须留在内网（ADR-10 E-5 禁止知识库全量、账本、审计、备份出网）；且企业内网无出网通道承载数据面 |
| 私有云 / 信创云提供 PG、对象存储、OIDC | WP01 N2 与 N10 待回填，未确认企业是否具备此类平台；即便具备，其版本、扩展（pgvector）、S3 兼容子集与运维接口均需重新验证，收益不确定而验证成本确定 |
| 复用企业内部既有数据库 / 文件服务 | D5 已明确"什么都没有"，无现成服务可复用 |
| 单机容器（最快验证档） | 单点、不可称可用，不满足内网与可持续要求（§3.2 已否决） |

## 理由

1. **没有可复用的平台**，全自建是唯一路径；决策的价值在于把范围与顺序固定下来，避免边做边猜。
2. **组件选择与已有技术栈一致**：PostgreSQL 17、RabbitMQ 4、MinIO、Keycloak、Harbor 均为 ADR-01~09 已确定的技术基线，本 ADR 不引入新组件，只确定自建范围。
3. **顺序按依赖而非按偏好排**：Harbor → PG → MinIO → MQ → Keycloak，使每一步的前置都已就绪，减少返工。
4. **观测与备份后置但不省略**：Prometheus/Grafana 与备份脚本不阻塞业务功能，但必须在 M5 加固阶段完成，否则 RPO/RTO 无法达标。

## 代价与风险

**代价**

1. **运维 0.5 人吃紧 → M0~M1 运维升全职**。零基础自建的安装、调试与补丁工作量翻倍，D5 是直接原因。M2 起按实际情况回落至 0.5。
2. 硬件一次性投入：应用服务器 ×2、数据库服务器 ×1、存储服务器 ×1、运维节点 ×1（研发计划 §14.1），且全部进关键路径（ADR-17）。
3. 自有运维责任：补丁、容量、备份、告警、故障恢复全部由团队承担，无供应商兜底。
4. 版本锁定成本：实施第一周须锁补丁版本并产出 SBOM，不使用浮动 `latest`（研发计划 §5）。`deploy/dev/docker-compose.yml` 中 MinIO 使用 `latest` 属 dev 特权，内网落地前必须换成 digest。

**风险与重新审视条件**

- **R4 运维量被低估**：监控信号为 WP05 超 10 人日。触发时优先提升 IaC 化程度，而非削减组件。
- **R8 容量超预期**：PG 500 GB NVMe 起步、MinIO 5 TB 可用起步，每月按实测增长率复核（研发计划 §6.1）；chunk 数逼近 200 万触发 ADR-15 分区评估。
- **重新审视条件**：企业后续提供可用的私有云 / 托管服务，且其 pgvector 支持、S3 兼容子集与运维接口验证通过 → 可重新评估部分组件迁出。在此之前，本决策不变。
- **单点风险**：PG 单实例、MinIO 单集群均为单点，靠备份 + 恢复演练（RPO ≤ 24h、RTO ≤ 8h）兜底，不做高可用冗余。这是首版的显式接受项。

## 验证方式

| 判据 | 验证方法 | 证据 |
|---|---|---|
| 最小链可启动 | `docker compose config` 静态校验 → `up -d` → `ps` 全绿 → PG 内 `SELECT extname, extversion FROM pg_extension;` 确认 `vector` 在列 | G0-18 容器清单 + 扩展清单 |
| 重启不丢数据 | `smoke.py --write --backend s3` → `docker compose restart`（不得 `down -v`）→ `--verify` | G0-19 `WP05-smoke-write.json` + `WP05-smoke-verify.json`（`passed: true`） |
| 无公网依赖 | 可出网机器 `docker pull` + `docker save` → 内网 `docker load` → **断网**后 `up -d`，确认无 DNS/网络超时重试 | G0-20 断网启动记录 + 离线包清单（含 digest） |
| 备份可恢复 | `pg_dump -Fc` → 独立库 `pg_restore` → 比对行数与 `content_digest` 一致；MinIO 侧补对象恢复小样 | G0-21 恢复记录 |
| 版本锁定 | 检查生产镜像均为 digest 或明确补丁 tag，无 `latest`；SBOM 已产出 | 镜像清单 + SBOM |
| 组件隔离 | 用户网段不可达 PG/AMQP/MinIO；仅反向代理与 Keycloak 可达 | WP01 连通矩阵实测（N5） |
| 监控与备份到位 | 告警规则生效；恢复演练达 RPO/RTO | WP47、WP48 报告 |
