# ADR-12 AI 质量定量验收

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-19 |
| 决策人 | 老大（业务负责人） |
| 影响范围 | G0 出口条件、上线门槛、评测集建设、模型选型、试点范围、结项报告口径；通过线数值由运营负责人签字锁定 |

## 背景

评审硬伤 🔴1：原计划只有 AC-01~30 这 30 项工程验收，没有任何一条针对 AI 生成内容质量的定量验收线。

这是一个结构性缺口，因为本系统的产能来自模型：工程验收能证明"任务能跑完、状态机正确、权限不越、文件不丢"，但**证明不了"生成的内容事实正确、可以直接过审、产品外观与参考素材一致"**。如果只有工程验收，系统完全可能以"全部 AC 通过"的状态上线，而运营每天在改事实错误、改错型号、改掉跨品牌串味——第一版的核心价值（少写稿）没有兑现，却已经宣布成功。

同时必须避免另一端的错误：把 AI 质量做成"主观感觉不错"的模糊评价。所以本决策要同时给出**可测指标**、**评测集规模**与**通过线的产生方式**。

## 决策

**我们决定新增 AQ-01~03 三项 AI 质量定量验收，纳入 G0 出口条件与上线门槛；通过线数值在 M0 末由运营负责人签字锁定。**

### 指标定义

| 编号 | 指标 | 草案目标（M0 校准后锁定） | 测量方式 |
|---|---|---|---|
| AQ-01 | 事实正确率 | ≥ 95% 条级正确；阻断级事实错误（参数/功效/竞品混入）= 0 | 评测集盲审，逐条核对事实引用 |
| AQ-02 | 首稿通过率 | 建立基线（草案 ≥ 50%），试点期趋势上升 | 试产 10 条人工审核结果 |
| AQ-03 | 产品一致性 | 外观/型号/颜色与参考素材一致 ≥ 90%；跨品牌事实混入 = 0 | 静态/Live 样张盲审 + 跨品牌对抗集 |

三条口径纪律（与打分工具一致，见 `tools/m0/wp04_eval/score.py`）：

1. **阻断级一票否决**：`blocking_errors` 非空即该条不通过，即使事实计数看起来全对。
2. **`pending` 不入分母**：未标注完的数据既不算 0 分也不算通过；无有效分母时报 `N/A`，阈值判 `NOT_EVALUATED`，总体为 `PARTIAL`。
3. **阻断类型词表固定**：`param` / `efficacy` / `competitor_brand` / `cross_brand` / `fabrication` / `injection_compliance`；词表外类型记 warn 但仍计入阻断。

### 评测集规模

| 项 | 要求 |
|---|---|
| 正常样本 | ≥ 30 条（≥3 品牌 × ≥10 条，含相近品类对抗） |
| 对抗样本 | ≥ 10 条（提示注入、跨品牌诱导、缺失证据、超长输入） |
| 来源 | 企业获准使用的真实 Brief 与笔记，**不用合成数据充数** |
| 标注 | 每条约好事实清单、必须提及、禁止提及、期望结构；两名运营背靠背标注，分歧仲裁；抽样 ≥10% 第三人复核 |
| 回归 | 每次换模型 / Prompt 大版本全量回归，结果入 `docs/model-evaluations/` |
| 通过线 | W2 评审会由运营负责人签字锁定（D1）；此后变更需同等签字 |

### 通过线的锁定与变更

- 通过线存放于 `tools/m0/wp04_eval/thresholds.json`，带 `version` / `locked` / `signed_by` / `signed_at` 字段。
- **签字前为草案（`locked: false`），不得作为任何验收结论引用**。
- 锁定后任何变更需同等签字（运营负责人），并保留历史版本。

### 未达通过线的处置

**不阻断系统工程验收，但试点范围收缩到达标模型/品类，并在结项报告如实标注——不允许把不达标说成达标。**

具体执行：

1. 系统工程验收照常进行（AC-01~30 证据齐全）。
2. AQ 未达标项在结项报告与上线结论中**显式标注为未达标**，写明实际值与目标值差距。
3. 试点范围收缩：只在达到通过线的模型 / 品类组合上运行真实项目，未达标组合不上线。
4. 收缩决定与理由写入 `docs/model-evaluations/` 与结项报告，供后续版本作为改进输入。
5. 禁止的行为：调低通过线以"凑达标"、用未标注样本充当评测结果、把 `PARTIAL` 报成 PASS、以"工程验收已全过"掩盖 AQ 未达标。

## 理由

**为什么 30 条工程验收不足以验收 AI 内容系统**

1. **验证对象不同**。AC 验的是"系统的行为"，AQ 验的是"产出的内容"。内容错了但系统行为完全正确是常态——状态机可以顺利走完八步，而生成的文案把型号写错、把 A 品牌功效安到 B 品牌上。
2. **工程验收无法覆盖语义正确性**。断言可以检查字段非空、结构合规、状态跃迁合法，但无法判断"这句话是否与参考素材一致"。
3. **事实事故的代价与工程缺陷不同**。越权、丢数据是系统事故；跨品牌事实混入是**对外发布的内容事故**，直接影响品牌与合规，且一旦发布难以完全收回。老大的核心诉求之一就是"不出事实事故"，这条必须有独立验收项。
4. **没有定量线就没有收敛目标**。模型与 Prompt 迭代需要明确的"够不够好"判据；否则换模型、改 Prompt 的决策只能靠感觉，试点期趋势也无从判断。
5. **AI 质量是业务价值的直接度量**。单篇合格内容成本下降的前提是首稿可用；AQ-02 首稿通过率就是这条业务指标的代理量。

**为什么通过线由运营负责人签字而非技术团队定**

- 通过线的实质是"运营愿意接受的稿件质量"，属于业务判断而非技术判断（D1 已拍板）。
- 运营负责人是内容审核结果的最终责任方，由其签字可保证通过线与真实审核标准一致。
- 签字机制使通过线成为**承诺**而非**建议**：后续变更需同等签字，避免为了过验收而私下放宽。

**否决的替代方案**

- **只做工程验收**：评审 🔴1 已否定。无法证明内容质量，存在"AC 全过但系统不可用"的失败模式。
- **用主观满意度替代定量线**（如"运营觉得可以"）：不可复现、不可回归、无法跨模型比较。**否决原因**：不可测即不可验收。
- **用少量样本快速验证**（如 10 条）：无法覆盖 3 品牌 × 相近品类对抗，单条噪声会主导结论。**否决原因**：统计意义不足，且相近品类是跨品牌串味的高发区。
- **用合成数据凑够条数**：无法反映真实 Brief 的语言与事实结构。**否决原因**：测出的通过率不代表真实表现。
- **未达标即阻断上线**：会导致 Live 图、数据闭环等已完成的硬要求因单一质量维度被整体否定，业务上不可取。**否决原因**：采用"收缩试点 + 如实标注"的处置，既不虚报也不全盘否定。

## 代价与风险

**代价**

1. 评测集建设与盲审人力：42 条样本 × 2 人份背靠背标注 + 仲裁 + ≥10% 第三人复核，是运营侧的真实投入（WP04 人日 4~6 → 6~8）。
2. 每次换模型 / Prompt 大版本需全量回归，是持续的固定成本。
3. 通过线一旦签字即受约束，后续想调整必须重新走签字流程。
4. 真实 Brief 依赖企业授权（E4，W1 截止），未到位则评测集只能是骨架（G0-13 当前为"部分完成"）。

**风险与重新审视条件**

- **R5 AI 质量达不到通过线**：概率中、影响高。应对为 M0 多模型盲测选优；不达标收缩试点品类，不虚报。监控信号为 AQ 盲审结果。
- **R6 供应商不稳定**：外部模型版本变更可能导致质量回退，需靠全量回归捕获。
- **重新审视条件**：连续多个版本 AQ-01~03 稳定达标且运营审核标准发生实质变化 → 通过线可按变更流程重新校准（仍需运营负责人签字）。

## 验证方式

| 判据 | 验证方法 | 证据 |
|---|---|---|
| 评测集达标 | 正常 ≥30 条（≥3 品牌 × ≥10，含相近品类）+ 对抗 ≥10 条，且来源为企业获准真实 Brief | G0-13：`datasets/eval/*.jsonl`、`datasets/eval/README.md`、`schema.md` |
| 基线已产出 | 候选模型 ≥2 个完成冒烟与盲审，产出 AQ-01~03 基线值 | G0-14：盲审记录 + 打分报告 |
| 通过线已签字 | 运营负责人逐项确认并签字；`thresholds.json` 的 `locked: true`、`signed_by` / `signed_at` 已填 | G0-15：签字页 |
| 产品一致性目检 | 静态图样张通过运营目检（外观/型号/颜色） | G0-16：样张对比页 |
| 未达标处置被执行 | 结项报告中未达标项显式标注；试点范围与 AQ 结果一致；无"调低通过线凑达标"痕迹 | 结项报告 + `docs/model-evaluations/` 归档 |
| 回归机制有效 | 每次换模型 / Prompt 大版本均有全量回归记录 | `docs/model-evaluations/` 归档目录 |
| 阻断级零容忍 | `blocking_errors` 与 `cross_brand_mentions` 计数为 0，且不因 `pending` 被稀释 | 打分报告（`score.py --strict` 退出码 0） |
