## 2. 为什么是 A（不选 C 的理由）

| 维度 | A 静态 + `api.js` | C React/Vite |
|---|---|---|
| 改动面 | 加 1 个 `api.js`；逐页把硬编码替换为取数 | 重写 33 页 + 迁移 2000+ 行 CSS 到组件体系 |
| 现有资产 | **33 页 HTML + 2076 行 CSS 全部保留** | 基本作废 |
| 构建链 | 无（`file://` 或静态服务直接开） | 需 Node + 打包 + 开发服务器 |
| mock 对接 | mock 已是 HTTP 服务，`api.js` 直连 | 需配 proxy / 环境变量 |
| E2E 工具 | Playwright 直开静态页 | 需先 build |
| 当前阶段适配度 | **demo 阶段目标 = 链路跑通并演示**（`docs/m0/OP-76-解法与责任分工.md` 定调） | 为长期产品迭代准备 |

**判断**：现在是 demo 阶段，目标是**把系统链路跑通并演示**。33 页 CSS 是资产，
不该在 demo 阶段推倒重来。React/Vite 的价值在长期组件化维护，**那是 demo
演示通过、产品确认长期做之后的事**，不是现在。

## 3. 路线 A 的落地要求

### 3.1 `api.js` 契约（唯一取数入口）

| 项 | 要求 |
|---|---|
| 位置 | `outputs/rednote-demo/api.js`（与 `app.js` 平级） |
| 基址 | `const API_BASE = window.REDNOTE_API_BASE || 'http://127.0.0.1:8787/api/v1'`（可切 mock / 真后端） |
| 包裹解包 | 单体贴 `{data, meta}`；列表贴 `{data, meta.page}`；**统一解包，页面只拿 `data`** |
| 错误 | 抛 `ApiError{code,message,details,retryable}`；`code` 只可能是 18 枚举之一 |
| 幂等 | 写操作自动带 `Idempotency-Key`（`crypto.randomUUID()`），**同一次用户操作复用同一键** |
| 不引入 | 不引 jQuery / axios / 任何 CDN（保持零依赖，与 mock 同风格） |

### 3.2 禁止事项（红线）

1. **页面里不得再出现新的硬编码业务数据** —— 新增数据一律走 `api.js`。
2. **不得把 mock 的数据形状当契约** —— 以 `contracts/draft/m4-openapi.yaml` 为准。
3. `api.js` 里的错误码 **不得自创**，只透传 18 枚举（对齐 `M4契约与幂等口径.md` §1）。
4. 现有 33 页的**静态演示态**（无后端时）必须仍可打开并展示 —— 用 `API_BASE` 探测失败降级到硬编码样例，**不得因为接不上后端就白屏**。

### 3.3 与 mock 的关系

mock（`tools/dev/mock_m4/`）已完成 **契约 45/45 操作全覆盖**（selftest 18/18）。
路线 A 下 `api.js` 可直接连 mock 做联调，**E2E 选 Playwright**
（项目已有 `playwright-chromium-headless` 技能与先例）。

## 7. 实现回填（A-1 ~ A-4，本轮实际做了什么）

> 回填日：2026-10-11（以磁盘实测为准；原文 §0-§6 不改）。静态页实际位置为 `services/backend/static/`（由后端 `REDNOTE_FRONTEND_STATIC_DIR` 同源托管），而非 §3.1 所写的 `outputs/rednote-demo/`。

### 7.1 A-1：`services/backend/static/api.js`
- 零依赖，导出 `window.api` 与 `window.ApiError`。接口：`get/list/post/put/patch/del/request`、`me/refreshSession/currentUser/clearSession`、`probe`、`newIdempotencyKey`。
- 页面只拿 `data`；`list()` 返回 `{data, page, meta}`。**契约实测：分页块是信封顶层的 `page`（`PaginatedEnvelope{data,page,meta}`），不是 `meta.page`**；api.js 优先读顶层 `page`，兼容 `meta.page`。
- 基址：`window.REDNOTE_API_BASE` 优先；否则 http(s) 同源 → `/api/v1`；`file://` → `http://127.0.0.1:8787/api/v1`。（与 §3.1 字面差异：后端已同源托管静态页，同源相对路径同时满足 Cookie 与 CSRF Origin 校验。）
- 错误：`ApiError{kind, code, message, details, retryable, status, requestId}`。`kind` 区分来源：`BACKEND`（后端标准错误体，字段原样透传）、`NETWORK`（无 HTTP 响应，`code` 恒为 `null`）、`PROTOCOL`（有响应但非 `{data,meta}` 信封，如代理 HTML，`code` 恒为 `null`）。客户端侧错误不使用任何错误码字符串，故不冒充后端枚举。
- 幂等 / CSRF / 并发：写操作自动带 `Idempotency-Key`（`crypto.randomUUID()`，不可用时回退 `getRandomValues`）；键固化在调用方传入的 `opts` 对象上，同一次用户操作重试传同一 `opts` 即复用同一键。`X-CSRF-Token` 取自 `GET /me` 的 `csrfToken`（仅存内存），首个写操作前自动拉取；写请求遇 403 时刷新 `/me` 并用同键重试一次；`refreshSession()` 供登录态变化后调用。`opts.ifMatch` 透传为 `If-Match`。
- 探测：`api.probe()` 永不 reject，返回 `ok | unauthenticated | unreachable | error`。

### 7.2 A-2 / A-4：已接线页面
- `project-overview.html`（试点）：`GET /me`、`GET /projects`（无 `?projectId=` 时取首项）、`GET /projects/{id}`、`GET /brands`、`GET /products`。真实渲染：项目编号、名称、阶段、截止与剩余天数、品牌/产品、负责人（仅当 ownerId 为当前用户时可显示姓名）、计划交付/发布、截止日期。其余区块（数量指标、交付进度、待办、费用、阶段记录、预算/Brief/参考素材）无对应端点或未接线，保持静态样例并标「样例」。
- `projects.html`（A-4 只读列表）：`GET /me`、`GET /brands`、`GET /products`、`GET /projects`（`limit`/`cursor`/`keyword`，「加载更多」依据 `page.hasMore/nextCursor`）。静态筛选条的计数与下拉选项属样例，连接后端后隐藏，仅保留关键字搜索（回车）。交付进度、已发布、协作者数无接口，显示「—」。
- 降级（红线 4）：不可达、未登录、接口报错一律保留页内原硬编码样例，仅在页首插入一条说明横幅；`api.js` 缺失同样不白屏。

### 7.3 A-3 验证
- 浏览器级：Playwright（node，本机已装 playwright 1.62.1 + chromium headless shell，未安装任何新软件）。脚本 `tools/dev/frontend_smoke/`（`run.sh` + `smoke.mjs` + README），库 `rednote_fe_smoke`，真实后端 dev 环境。覆盖：已登录真实数据；网络中止 / 纯静态服务 / 未登录降级且无 `pageerror`；503 标准错误体透传 code；api.js 错误解包、幂等键复用、CSRF、If-Match、真实 POST。连续两次 ALL PASS。

### 7.4 与定案的偏差 / 未做项
1. 错误码口径：`platform/errors.py::ErrorCode` 实为 **17** 个成员；《M4契约与幂等口径》称 18 个，差的一个应是 500 专用的 `INTERNAL_ERROR`（刻意不在 `ErrorCode` 内）。api.js 对后端 code 原样透传，`isKnownCode()` 只核对这 17 个。
2. 契约以 `contracts/openapi.json`（非 `contracts/draft/m4-openapi.yaml`、非 mock 形状）为准。
3. 未做：登录页接线（`login.html` 未动，浏览器内尚无登录入口；联调用 dev 旁路 `POST /api/v1/dev/auth/login` 建会话）；其余 31 页；写操作页面接线；筛选/排序；`/events` 轮询。
4. 后端缺口：项目详情只给 `ownerId`/`brandId`/`productId`，无用户目录端点（负责人/协作者姓名）；无项目级聚合指标端点（生成数/通过数/交付进度/已发布，列表与总览均需）；无项目协作者列表读端点的前端接线验证（未核实）；列表无总数 `total`（`page` 仅 `hasMore/nextCursor`）。
5. CDN 外链（fonts.googleapis.com、cdnjs）内网不可用，本轮未处理。
