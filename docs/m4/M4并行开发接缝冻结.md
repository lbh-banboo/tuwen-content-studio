## 1. 为什么需要冻结

M4 有 **10 个包、两条子链**（数据链 WP36→37→38→39→40→41；管理链 WP42→43→44→45），
两条链在 **WP38 指标快照**处分叉。契约一旦定错，下游返工面最大的正是 WP38（见 M4 计划 §7.3）。

并行开发下，**唯一能引发「无法自动解决」冲突的资源是迁移链**：两个分支各写一个迁移，
`alembic` 会得到 **Multiple head**，回滚序列不再唯一。

因此本文件的目的与 M2 相同：**把「谁可以写什么」提前钉死，让冲突在写之前就不可能发生，
而不是在 merge 时靠人工分辨。**

## 3. 数据库隔离（并行必需的硬条件）

沿用 M2 §3，一字不改：

1. 每个并行会话使用**独立私有库**，库名由**包号派生**：`rednote_test_wp36`、`rednote_test_wp38` …
2. 通过环境变量 `REDNOTE_TEST_DATABASE_URL` 指定；**不得硬编码测试 DSN**
   （判据 `tools/quality/check_test_db_isolation.py`）。
3. **DSN 方言后缀口径**（ISS-174）：`REDNOTE_TEST_DATABASE_URL` 必须带 SQLAlchemy 方言前缀
   `postgresql+psycopg://`；喂给 `psycopg.connect()` 前须 `.replace("postgresql+psycopg://", "postgresql://", 1)`。
   **只能用 `.replace()`**，新增 DSN 字面量会被隔离判据抓。
4. **跑真库测试前先查有无其他连接**（技能铁律 17「跑真库前确认共享库静止」，ISS-160）：
   ```sql
   select datname, state, left(query, 60)
     from pg_stat_activity
    where datname is not null and pid <> pg_backend_pid();
   ```
   **同名库上有其他会话的 active 连接 ⇒ 拒跑**，不要"先跑再看"。

> ✅ **2026-10-11 已判据化（WP-DEBT-04 的"同名库有连接则拒跑"半边）**：判据 = `tools/quality/check_shared_db_quiet.py`
> 的 `assert_quiet(dsn, scope=...)`（E1~E4）。它在 CI 上 `--ci` 显式 SKIP（runner 以
> `services: postgres` 独占库，"有没有别人在用"无区分度），**真实载体**是收口期
> `tools/m1/rerun_all_evidence.py` 里"任何子进程启动之前"的那一次调用 ——
> 也就是本小节这段 SQL 的**机械化替身**。此处保留原 SQL 供人工排查时手动执行。

## 4. 迁移的并行协议（最容易出事的地方）

### 4.1 铁律：**契约先行线禁止写 `migrations/versions/`**

| 允许 | 禁止 |
|---|---|
| `contracts/draft/**`（草案区） | `contracts/openapi.json`（主 agent 串行导出） |
| `docs/m4/M4-DDL草案.md`（**文本草案**） | `migrations/versions/*.py`（**禁建**） |
| `tools/dev/mock_m4/**`（只读样例） | `migrations/env.py`（禁改） |

**分支只能交 DDL 的文本草案；建迁移是主 agent 的独占动作。** 这是 M2 已验证的办法。

### 4.2 分支的测试怎么建表（关键机制，别自己发明）

沿用 M2 §4.1：分支**不靠迁移建表**，靠
`Base.metadata.create_all(tables=[…本包的表…])` 在 module 级 fixture 里建。

**为什么**：分支拿不到本包的迁移文件（迁移归主 agent），所以测试不能依赖 `alembic upgrade`。
代价是**测试建的表结构 = ORM 元数据，不等于迁移建的结构** —— 因此主 agent 并入迁移后
**必须再跑一次真库往返判据**（§4.3），补上这道缝。

### 4.3 并入后必过的往返判据

每个 M4 迁移并入后立即跑：

```
upgrade head → downgrade base → upgrade head
```

载体：`test_migration_roundtrip.py`（静态扫描）+ `check_migration_roundtrip.py`（真库往返）。

**`downgrade` 硬约束**（ISS-79 教训，修复已在工作树）：
- **不得删除跨包共用函数**（`rednote_reject_mutation()` 类）；
- 函数删除范围必须**按归属取**（`owned_functions()`），**不得**用 `all_trigger_ddl()` 的并集。

> 19 张表是本项目**最大的一次迁移增量**（M4 计划 §5）。M5 的 WP47 回滚演练会整体
> `downgrade base`，M4 每个新迁移都会被逆序执行 —— 往返判据不是可选项。

### 4.4 迁移文本必须是**化石**（ISS-191）

迁移里**不得活引用**取值域（不得 `from rednote.modules.x.types import SOME_ENUM` 后循环它）。
一旦活引用，parity 判据会恒绿：类型改了迁移也跟着改，两边永远一致 —— 判据**永不报警**。

**⇒ 迁移里的取值域必须写成字面量**，由 parity 判据反向核对。

## 6. 分支必须遵守的铁律

1. **`migrations/versions/` 禁写**（§4.1）。
2. **共享文件禁改**（§7.1 的 26 处），只写自己的模块 + 自己的测试 + 自己的说明文档。
3. **一包一提交** `feat(m4): WP<NN> <一句话>`；**证据不得与代码同提交**
   （正确顺序：代码/文档提交 → 重跑证据 → **纯证据提交**）。
4. **收口复跑用 `rerun_all_evidence.py`**，不许手写 shell 清单（判据纪律第 14/15 条）。
5. **同模块子包拆分**（WP38/WP39 同在 `modules/metrics/`）：**先在一次提交里建好空的
   `metrics/__init__.py` 与目录骨架**，再各写各的子包；否则两个分支都会 `mkdir` 同一目录。
6. **已存在的表/模块一律复用不新建**：`knowledge_proposals`（WP23）、`usage_ledger` /
   `cost_estimates`（WP25）、`version_nodes`（WP11）、`provider_calls`（WP16）。
   **重复建表是 M4 最容易犯的错**（M4 计划 §7.7 已点名风险）。
7. **缺失不填 0**（导入口径）；**NULL / 0 / 约数三者分离**（WP38 核心断言）。
8. **`metric_latest` 是可重建缓存**，不是历史权威来源；`metric_observations` **只追加**。
9. 新增 import 同步 `pyproject.toml`；新增本地 `import check_xxx` 登记 `LOCAL_IMPORT_NAMES`（WP-DEBT-01）。

### 7.3 新增判据脚本必须同步三处（判据纪律第 14 条）

① CI 门 3 步骤列表 + `collect_regression_evidence.py::REQUIRED_CI_STEPS`（**两处**，由
