# WP37 链接规范化 / 笔记去重 / 发布内容状态：说明

> 依据：`docs/m4/WP37-实施约定.md`（已拍板，范围不扩）、`docs/m4/WP36-ddl-草案.md` §1.4、`contracts/draft/m4-openapi.yaml`。
> 代码：`services/backend/src/rednote/modules/delivery/`（与 WP36 共用目录）。测试：`services/backend/tests/test_delivery_wp37.py`。

## 1. 做了什么

| 件 | 位置 | 说明 |
|---|---|---|
| 规范化纯函数 | `urls.py` `normalize_url` | 标准库、无 IO、幂等；scheme/host 小写、去默认端口、去 fragment、去尾部 `/`、查询参数排序、去通用追踪参数 |
| 登记链接 | `service.add_publication_link`、`POST /publications/{publicationId}/links` | 项目内同 canonical 409；跨项目命中非管理者 409；管理者放行并带 `crossProjectConfirmed=true`；首条链接回填 `publications.url_canonical` |
| 跨项目查重 | `GET /publication-links?canonicalUrl=` | 分页；非管理者只见自己有活跃成员关系的项目的命中 |
| 内容状态 | `service.verify_publication`、`POST /publications/{publicationId}/verifications` | `result ∈ {VERIFIED, UNVERIFIED}`，写 `publications.content_state` |
| distinct 计数 | `repository.count_distinct_publications(project_id, canonical_url=None)` | 按 `publication_id` 去重；无端点 |

## 2. 错误翻码（新增部分）

| reason | 协议码 | 说明 |
|---|---|---|
| `PUBLICATION_NOT_FOUND` | 404 `RESOURCE_NOT_FOUND` | 先按 id 反查项目再鉴权；非成员的 404 被重写成与"不存在"同文案同 details 键 |
| `LINK_URL_INVALID` / `VERIFY_RESULT_INVALID` | 422 | 空、过长、非 http(s)、无主机、含凭据、端口非法、含空白或控制字符 / result 不在两值内 |
| `LINK_CANONICAL_TAKEN` | 409 `DUPLICATE_PUBLICATION` | 项目内重复；details 带本项目内的 `publicationId` 与 `samePublication` |
| `CROSS_PROJECT_NOTE` | 409 `DUPLICATE_PUBLICATION` | 别的项目已登记且调用者无 `CONFIRM_CROSS_PROJECT_NOTE`；`details.crossProject=true`，不含对方项目 id / 名称 / 发布 id |

鉴权：`DELIVER`（写）。结项项目的 `DELIVER` 被 `permissions.py` 硬拒（403），对管理者同样。`GET /publication-links` 只要求登录，可见性在查询里收窄。

## 3. 已知缺口（Q2 关闭的直接后果，务必知悉）

1. 不识别短链、不做短链 ⇄ 长链等价：同一条笔记的短链与长链会被当成两条不同链接。验收项「短链与长链不重复」**本包不承诺**。测试 `test_short_and_long_are_not_unified_known_gap` 钉住这一点。
2. `link_kind` 只产出 `LONG`（有非根路径或查询串）/ `OTHER`（只有主机）。这不是语义判定，`SHORT` 取值域保留但没有产出路径（有测试断言）。
3. 不从 URL 抽 `note_id`；不返回「长链」字段。
4. 追踪参数名单只含通用约定（`utm_*`、`fbclid`、`gclid`、`dclid`、`gbraid`、`wbraid`、`msclkid`、`yclid`、`mc_cid`、`mc_eid`），非小红书调研；`xsec_token` 之类平台参数一律保留。
5. 不做 percent-encoding 大小写归一、不做路径大小写归一。

## 4. OP（待产品确认的取舍）

- **OP-37-1 管理者确认 = 管理者亲自登记**（约定 §3.3）。响应比契约多一个布尔 `crossProjectConfirmed`（契约扩展）。运营遇跨项目命中得 409，需联系管理者代登记；管理者无法"事后批准运营的登记"。若要"提交 → 审批"两步流需另开拍板（新状态与端点）。
- **OP-37-2 `Idempotency-Key` 只校验长度、不回放**。`publication_links` 没有幂等键列（迁移范围仅 `project_id` + 唯一索引），所以同一请求重试得到 409 重复（`samePublication=true`），不是 200 回放。`verifications` 天然幂等（同值重写）。若要真回放需加列与迁移。
- **OP-37-3 `PublicationVerify.note` 接收但不落库**：`publications` 无对应列，本包不扩表。
- **OP-37-4 `GET /publication-links` 的 `canonicalUrl` 查询值先过规范化**（对已规范值恒等），所以贴原始链接也能命中；非法值 422。

## 5. 期望的迁移内容（主线写）

对 `publication_links`：

1. `ADD COLUMN project_id UUID NOT NULL`（存量表为空，直接 NOT NULL；若有存量行需先回填 `UPDATE ... SET project_id = publications.project_id`）。
2. `ADD CONSTRAINT fk_publication_links_project_id_projects FOREIGN KEY (project_id) REFERENCES projects (id) ON DELETE RESTRICT`（命名按 `NAMING_CONVENTION`，以 `check_migration_model_parity` 对账为准）。
3. `CREATE UNIQUE INDEX uq_publication_links_project_canonical ON publication_links (project_id, canonical_url)`。
4. 保留 `ix_publication_links_canonical`、`ix_publication_links_publication`、`ix_publication_links_raw` 不动。
5. `downgrade`：`DROP INDEX uq_publication_links_project_canonical`、`DROP CONSTRAINT`（FK）、`DROP COLUMN project_id`，只删自有对象。

#### 核实出的既有问题（WP36，本包未改）

**item 级路径对「非成员」与「不存在」的响应体不同形。** 2026-10-26 实测 `GET /deliveries/{id}`：

| 情形 | 状态码 | message | details |
|---|---|---|---|
| 别项目的交付（非成员） | 404 | 项目不存在或无权访问。 | `{projectId}` —— **带出了该交付所属项目的 id** |
| 不存在的交付 | 404 | 交付记录不存在。 | `{reason: DELIVERY_NOT_FOUND, deliveryId}` |

状态码相同，但 message 与 details 都不同，调用者能据此区分「存在但无权」与「不存在」，并拿到项目 id，与 WP36 说明文档声称的「同形 404 防枚举」不符。WP36 的 `test_non_member_gets_404_not_403` 只断言状态码，没比较响应体，所以没抓到。**已修（2026-10-26，用户拍板范围=只修 WP36/WP37）**：抽出共用的 `api.py::_authorize_item`，非成员的 404 重翻成与「不存在」完全一致的 404（403 原样抛出）；`_authorized_delivery`（WP36 的 4 个交付端点）与 `_authorized_publication`（WP37 的 2 个发布端点）都走它。新增 `test_non_member_404_body_is_indistinguishable_from_not_found_on_item_paths`（比较响应体、断言项目 id 不出现）；撤掉修复后它与 WP37 的同形用例均转红。

**其余模块未修**：content / batches / quality / media / review / feedback / exports 等模块的 item 级路径在代码层面是同样的写法（全仓约 56 个 item 级操作），但**尚未实测**是否真的泄露。登记为 **ISS-225**（MAJOR / OPEN）。
