# M4 契约与幂等口径

> 编制日：2026-10-08　配套：`contracts/draft/m4-openapi.yaml`（34 paths / 45 ops / 87 schemas）
> 依据：`services/backend/src/rednote/platform/errors.py`（**18 个 `ErrorCode`，权威**）、
> `docs/m4/M4-DDL草案.md`（部分唯一索引即幂等键的载体）、`templates/metric_import_field_guide.md`（导入口径）。

---

## 0. 一句话

**M4 的所有写端点里，凡可能被重复提交的，都必须有一个可判定「是不是同一笔」的键；
而键的最终载体是 DB 的「部分唯一索引」——不是应用层的一段 if。**

---

## 1. 错误码口径（**只许取 18 个，不得自创**）

来源 `ErrorCode`（`platform/errors.py`）。`INTERNAL_ERROR` 是 500 专用单值字面量，**不在枚举内**。

| 码 | HTTP | 可重试 | M4 典型触发点 |
|---|---|---|---|
| `MALFORMED_REQUEST` | 400 | ❌ | CSV 结构损坏、JSON 不合法 |
| `SESSION_EXPIRED` | 401 | ❌ | 会话失效 |
| `PERMISSION_DENIED` | 403 | ❌ | 非本项目成员改交付 |
| `EXTERNAL_POLICY_DENIED` | 403 | ❌ | **适配器认证失败即停**（WP40） |
| `RESOURCE_NOT_FOUND` | 404 | ❌ | 交付/发布/导入批次不存在 |
| `INVALID_TRANSITION` | **409** | ❌ | 交付状态机、导入状态机、结项后停止生产 |
| `IDEMPOTENCY_CONFLICT` | **409** | ❌ | **同幂等键不同内容** |
| `DUPLICATE_PUBLICATION` | **409** | ❌ | **短链/长链规范化后重复**（WP37） |
| `EVENT_HISTORY_EXPIRED` | 410 | ❌ | SSE 断点过旧 |
| `VERSION_CONFLICT` | **412** | ❌ | 乐观锁 `lock_version` 不符 |
| `UPLOAD_TOO_LARGE` | 413 | ❌ | 导入文件过大 |
| `VALIDATION_FAILED` | **422** | ❌ | 字段校验（词表、格式、量级） |
| `BUDGET_EXCEEDED` | **422** | ❌ | 预算不足 |
| `DIRECTION_UNVERIFIED` | 422 | ❌ | 方向缺已验证样例 |
| `PRECONDITION_REQUIRED` | 428 | ❌ | 缺 `If-Match` |
| `RATE_LIMITED` | **429** | ✅ | 适配器限速 |
| `DEPENDENCY_UNAVAILABLE` | 503 | ✅ | 依赖不可达 |

> **只有 429 与 503 可重试。** 计费类写操作盲目重试 = 重复扣费。
> 错误体 `ErrorBody` = `{code, message, details, retryable}`；`details` 返回前统一脱敏。

## 2. 幂等键总表（M4 九处）

> ⚠️ **本节口径由磁盘派生，不手写**（2026-10-11 更正）。
> 旧版写「五处」，与契约实际不符 —— 契约里标了 `IdempotencyKey` 的写操作是 **9 个**。
> 核对命令（引用本数前先跑）：
> ```bash
> python -c "import yaml;s=yaml.safe_load(open('contracts/draft/m4-openapi.yaml'));\
> print(sum(1 for p,v in s['paths'].items() for m,d in v.items() \
>   if m in('get','post','put','patch','delete') \
>   and any(isinstance(x,dict) and x.get('\$ref','').endswith('IdempotencyKey') for x in d.get('parameters',[]))))"
> # 期望：9
> ```

| # | 端点 | 幂等键 | 载体（DB） | 重复提交行为 | DDL 现状 |
|---|---|---|---|---|---|
| 1 | `POST /deliveries` | `Idempotency-Key` 头 | **未定**（无自然业务键） | 同键 ⇒ 返回同交付行（200），不新建 | ⚠️ 缺列、缺索引 |
| 2 | `POST /deliveries/{id}/deliver` | `Idempotency-Key` 头 | `deliveries.state` + `uq_usage_ledger_idempotency`（如连带计费） | 已 `DELIVERED` ⇒ 200 幂等；**不重复计费** | ✅ 状态机已建 |
| 3 | `POST /deliveries/{id}/replace` | `Idempotency-Key` 头 | **未定**（`replaces_delivery_id` 可判，但非唯一约束） | 同键 ⇒ 返回同替换行（200）；**不追加第二条替换链** | ⚠️ 缺列、缺索引 |
| 4 | `POST /export-items` | `Idempotency-Key` 头 | **未定** | 同键 ⇒ 返回同导出项（200），不重复导出 | ⚠️ 缺列、缺索引 |
| 5 | `POST /publications` | `Idempotency-Key` 头 | `uq_publications_project_key`(`project_id`,`publication_key`) | 同业务键 ⇒ `DUPLICATE_PUBLICATION`（409） | ✅ 业务键已建；**`Idempotency-Key` 无列** |
| 6 | `POST /metric-observations` | `Idempotency-Key` 头 | `uq_metric_observations_natural`(`publication_id`,`metric_definition_id`,`observed_at`,`source_type`) | 已存在 ⇒ 返回既有行（200），不新增 | ✅ 已建 |
| 7 | `POST /metric-imports` | `Idempotency-Key` 头 | `uq_metric_imports_idempotency`(`idempotency_key`) `WHERE NOT NULL` | 同键 ⇒ 返回同批（200），不新建 | ✅ 已建 |
| 8 | `POST /metric-imports/{id}/confirm` | `Idempotency-Key` 头 | `metric_imports.state` 状态机 | 已 `CONFIRMED` ⇒ 200 幂等返回；**不重复写观测** | ✅ 状态机已建 |
| 9 | `POST /billing/reconciliations` | `Idempotency-Key` 头 | `uq_usage_ledger_idempotency`（WP25 已建） | **重复回执不重复收费** | ✅ 已建 |

> ⚠️ **本次更正发现的真缺口（不是文档笔误，是 DDL 欠账）**：
> 契约给 `POST /deliveries`、`/deliveries/{id}/replace`、`/export-items`、`/publications`
> 四个端点声明了 `Idempotency-Key`，但 `M4-DDL草案.md` 里
> **`deliveries` / `export_items` 既无 `idempotency_key` 列，也无对应部分唯一索引**。
> 这意味着：**键只在契约里存在，DB 层无载体** ⇒ 幂等会退化成应用层 `if`
> —— 正是本文件 §0 明令禁止的形态，也是 ISS-95 家族（"声称有防线"）的复发点。
> **处置**：登记为 **WP36 开工前置**（建列 + 部分唯一索引），并在
> `M4-DDL草案.md` §1.2 / §1.3 补列。本行口径修正**必须先于 WP36 编码**。

### 2.1 键的取值规则

- 长度 8–128，建议 UUIDv4 或 `<op>:<biz_id>:<version>`。
- **同键 + 同请求体** ⇒ 幂等（返回首次结果）。
- **同键 + 不同请求体** ⇒ `IDEMPOTENCY_CONFLICT`（409）。**必须比对请求体指纹**，不能只看键存在。

> ⚠️ 这是本项目的 **ISS-95 家族**高发点：只在 docstring 里写「同键不同内容会报 409」，
> 而代码里没有指纹比对 → 声称的防线不存在。**M4 每个幂等端点都要有独立断言**
> （同键同体 → 幂等；同键异体 → 409），且断言必须真跑。

## 3. 状态机与合法迁移（`INVALID_TRANSITION` = 409）

| 实体 | 状态 | 合法迁移 |
|---|---|---|
| `deliveries` | `PREPARED → DELIVERED` / `PREPARED → CANCELLED` | 其余一律 409；**替换不改旧行 state** |
| `metric_imports` | `DRAFT → PREVIEWED → CONFIRMED`；`* → FAILED` | **未 `PREVIEWED` 就 `CONFIRMED` ⇒ 409** |
| `publications.state` | `DRAFT → PUBLISHED` / `→ UNKNOWN` | |
| `publications.content_state` | `VERIFIED ⇄ UNVERIFIED` | **抓取失败只落 `UNVERIFIED`，不得推成删除** |
| `experiments` | `DRAFT → RUNNING → CLOSED` | |
| `project_closures` | 结项后**停止生产但可补数据**；重开 = **追加新行** | |

## 4. 并发与乐观锁

- 可并发改的表带 `lock_version`（`deliveries` / `publications` / `metric_imports` / `reports` / `experiments`）。
- 提交时带 `If-Match: <lock_version>`；不符 ⇒ `PRECONDITION_REQUIRED`（428，缺头）或 `VERSION_CONFLICT`（412，值不符）。
- **预算类**（WP43）沿用 WP25 的三条**条件 UPDATE**（`reserve_budget` / `release_budget` / `settle_budget`），
  守恒式 `committed + reserved ≤ limit`；**不要**用「读-改-写」。

## 5. 只追加 / 不可变（触发器）

| 表 | 保护 | 断言 |
|---|---|---|
| `metric_observations` | `rednote_reject_mutation()` | UPDATE / DELETE 被拒（`23001`） |
| `report_versions` | `rednote_reject_mutation()` | 旧报告不因新指标改写（AC-29） |

**复用函数，不重建**；`downgrade` **按归属删函数**，不得用 `all_trigger_ddl()` 并集（ISS-79）。

## 6. 导入口径（`metric_import_rows` 必须与此一致）

- 11 列：`publication_key, metric_code, metric_scope, observed_at, value, raw_value, precision, availability, source_type, evidence_ref, note`。
- **校验规则唯一来源**：`tools/m0/wp03_data/validate_import.py`（词表 + 告警码）。
  **导入器不得另写一套词表**；告警码原样落入 `metric_import_rows.warnings`。
- **缺失不填 0**；`NULL / 0 / 约数` 三者分离；文本类指标 `value` 必须为空。
- **预览确认后才写正式观测**（`CONFIRMED` 才落 `metric_observations`）。
