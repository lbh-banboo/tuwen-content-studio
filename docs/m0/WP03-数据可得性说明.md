### 2.1 实测协议覆盖的字段（14 个）

**指标类（8 个）**：浏览/阅读量、曝光量（隔离字段）、点赞数、收藏数、评论计数、评论正文、商品链接点击**次数**、商品链接点击**人数**。

**发布登记类（6 个）**：笔记链接、平台笔记标识、发布时间、是否投流、已知投流信息、发布状态。

每个字段在协议中均给出：字段名、`metric_code`、**平台可能口径（明确标注为假设 · 平台侧字段待实测确认）**、测试方法编号、预期可得性（统一预填「未知」，防确认偏误）、**实测结论列留空待回填**、证据引用列。

### 2.2 四种可得性等级（G0-10 判定词表）

| 等级 | 定义 | 门槛 |
|---|---|---|
| `AUTO` | 有官方接口或授权通道，且**实测成功** | **未经实测不得标自动**（G0-11） |
| `IMPORT` | 可后台手工导出，或截图 OCR 后人工确认 | 须实测确认该动作可完成 |
| `MANUAL` | 只能人眼读、人手填 | 须写明读取位置与耗时量级 |
| `UNAVAILABLE` | 当前权限与合规前提下无法以任何方式获取 | 须写明不可得原因 + 替代路径 |

### 2.3 口径规范化（六条硬口径，已可机检）

1. 阅读量与曝光量**不得混加**（两字段物理隔离，分别求和）
2. 点赞数支持约数（`1.2 万` 保留原值字符串 + `APPROXIMATE`，**不得伪装精确**）
3. 评论计数与评论条数**分开**
4. 点击次数与点击人数**分开**（且点击类必须写明统计窗口）
5. 统计窗口必须随值登记（不同窗口不可比较、不可相加）
6. 每个指标有自己的观测时间（汇总必须显示时间差，不声称整行同一时刻采样）

### 2.4 缺失表示规范

- **NULL 与 0 的区别**：`0` 是合法的真实观测值；「拿不到」必须留空 + 标状态。**缺失不填 0**（需求 §12.3）。
- **六种字段状态**：`ACQUIRED`（已获取）/ `NOT_PROVIDED`（未提供）/ `NO_PERMISSION`（无权限）/ `NOT_APPLICABLE`（不适用）/ `FETCH_FAILED`（获取失败）/ `PENDING`（待确认）。
- **只有 `ACQUIRED` 参与汇总**，其余五种一律排除，且界面必须显示排除原因。
- **约数保留原值字符串**：`raw_value` 原样存 `"1.2 万"`，`value` 存规范值，`precision=APPROXIMATE`。

### 2.5 三条导入路径（需求 §12.2 要求的第一版必备）

| 路径 | `source_type` | 关键人工确认点 |
|---|---|---|
| CSV / XLSX 导入 | `CSV_IMPORT` / `XLSX_IMPORT` | 上传后必须预览：字段映射、缺失行、口径告警、重复行 |
| 截图 OCR 后确认 | `SCREENSHOT_OCR` | **OCR 结果一律不得直接入库**，逐值人工确认 |
| 人工录入 | `MANUAL` | 缺失项必须显式选六态之一，界面不得提供「留空」 |

### 2.6 校验工具能力（纯标准库，已实跑）

- `--file <csv>`：输出行数、逐条问题（行号 + 字段名 + 代码 + 说明）、按代码汇总、结论。
- 字段级错误（ERROR）：必填、枚举、主键格式、列数、表头、时间戳（缺时区/格式/未来/过旧）、数值类型、文本类误填 value 等。
- **口径违规告警（WARNING）**：`value=0` 但状态为缺失、约数标 `EXACT`、曝光填进 `VIEW_COUNT`、点击类窗口缺失、`AUTO_API` 无证据、量级不一致、中文引号、重复行等。
- `--selftest`：内置合成数据覆盖全部错误分支，输出断言计数，退出码 0/1。
- 退出码：`--file` 为 0（无 ERROR）/ 1（有 ERROR）/ 2（用法或文件不可读）；`--selftest` 为 0/1。

## 5. 若全部不可得：处置方案（对应决策 D3）

**这是本工作包最重要的预案。** 研发执行计划 V2.0 决策 D3 已拍板：**数据反馈以人工导入为第一版常态**。

### 5.1 预期管理

- 小红书对普通企业基本不开放笔记后台数据接口。**F01–F14 全部为 `UNAVAILABLE` 属于预期内结果**，不视为缺陷、不视为 WP03 失败。
- 执行计划已将该风险（原 R1）**降级为已接受的产品形态**，验收标准改为「**明确不可得提示 + 导入替代路径顺畅**」。
- 因此「全不可得」**不阻塞上线**，也不构成 G0 不通过的理由。

### 5.2 具体处置（五条）

1. **不阻塞上线。** 第 8 步数据回收走「人工录入 + CSV/XLSX 导入 + 截图 OCR 确认」三路径，本工作包已全部备好（模板 + 字段说明 + 校验工具）。
2. **产品行为按「明确不可得」设计。** 界面必须显示「该字段当前不可自动获取」并引导至导入路径；**不得静默留空、不得显示 0 冒充数据**（这正是校验工具 `VALUE_ZERO_ON_MISSING` 告警要防的事）。
3. **回写需求。** 按执行计划 §5.3 与硬伤 🔴3 的处置，将渠道清单结论回写需求说明 §1.3。
4. **保留未来接入位。** 数据模型保留 `source_type` 字段；未来若出现合规渠道，作为新增来源接入，**不改表结构**。
5. **如实上报。** 在 G0 评审会上明确写出「Q3 的结论是全不可得」。**禁止**为凑 G0 通过而虚报可得性（M0 执行手册 §5 红线 2、3）。

### 5.3 部分可得时的处置

- 可得字段按等级接入；不可得字段走人工/导入路径。
- **不得因为"部分字段能自动拿"就宣称"数据自动回收已打通"** —— 口径、时间差、覆盖度必须一并说明（需求 §12.4）。
