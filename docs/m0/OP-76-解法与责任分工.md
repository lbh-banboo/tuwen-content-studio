## 2. 虚拟化方案：三件事

### 2.1 Live 封装桩（`LivePackStub`）

| 项 | 做法 |
|---|---|
| 输入 | 静帧文件 + 动态文件 + `live_profile_id`（可用占位 profile） |
| 输出 | 按封装规格 §3 的 `LivePackResult` 结构返回：`mediaVersionId`、`componentFileIds`（`STILL`/`PAIRED_MOTION`/`MANIFEST`/`PREVIEW`）、`previewFileId`、`metadataValidation` |
| 真实部分 | **文件结构**真实写入（静帧 + 动态 + manifest 三个文件真的落对象存储） |
| 虚拟部分 | **配对元数据的"平台可识别性"** 是桩 —— 不声称 Apple Photos 能识别 |
| 标记 | 所有产出带 `synthetic=True` 与 `live_profile_id` 指向**占位 profile**（非 VERIFIED） |

**关键约束**：桩 **不模拟"发布成功"** —— 发布是外部平台行为，桩只到"产出可交付的封装资产"为止。发布环节在 demo 里用状态标记（`EXPORTED` / `PUBLISHED_SIMULATED`）。

### 2.2 合成素材生成器（`tools/dev/m0/make_live_sample.py`）

不依赖供应商、不依赖真机，本机生成一组样本：

| 产出 | 怎么做 |
|---|---|
| 静帧 | Pillow 画一张竖版 3:4 图（编程生成，无版权问题） |
| 动态 | FFmpeg 生成 3 秒 MOV（若本机有 ffmpeg）；**无 ffmpeg 时用占位字节 + 标记** |
| manifest | JSON，写配对关系 |
| 打包 | 复用 `files/storage.py` 的 `assemble` 落成一"组" |

**判据**：生成物能被系统读回、结构完整、每个文件都有 sha256。**不判"能否被相册识别"**（那是真机的事）。

### 2.3 前端假数据 + 显式标记

`delivery.html` 已写「Live 按已验证格式输出 HEVC + HEIC 配对」——这句**目前是假的**（真机 0 证据）。修法：

- 后端返回的 Live 资产带 `verification: "SYNTHETIC"` 字段
- 前端把"已验证"字样改为「**合成模式（真实设备验证待上线前完成）**」，用明显配色区分
- 演示时不冒充已验证

## 3. 解封 WP28 的准确口径

| 部分 | Demo 阶段做不做 | 标记 |
|---|---|---|
| Live 生成任务（`KIND_MEDIA_GENERATE` 的 LIVE kind） | ✅ 做 | `SYNTHETIC` |
| Live 封装（`LivePackStub`） | ✅ 做 | `SYNTHETIC` |
| Live 与静态共用段落/素材绑定 | ✅ 做（复用 WP27 的 `media_versions`） | 真实 |
| 计费预占（按组） | ✅ 做（复用 WP25） | 真实 |
| `live_profiles` 表 | ✅ 建表，**只放占位 profile**（`state=PLACEHOLDER`） | 标记 |
| **真机发布验证** | ❌ 不做，登记为**上线前验收项** | `BLOCKED_ON_EXTERNAL` |
| `metadataValidation` 的"平台真实兼容" | ❌ 不声称 | — |

**OP-183 的关闭条件改写**：原写"等 OP-76 闭合"。修订为 —— **"系统侧链路完成 + 全部产出标注 SYNTHETIC 且无任何'已验证'字样"即视为关闭**；真机验证（OP-76）**转为上线前 G0 验收项**，不再阻塞开发。

---

## 4. 必须守住的线（否则就是造假）

1. **不许出现"已验证"字样**：任何 UI / 文档 / API 字段，凡涉及未做真机验证的 Live 能力，必须标 `SYNTHETIC` 或"待设备验证"。
2. **桩不冒充成功**：`LivePackStub` 不返回"发布成功"，只返回"封装资产已产出"。
3. **`live_profiles` 不带 VERIFIED**：占位 profile 的 state 只能是 `PLACEHOLDER`，代码里禁止把 `PLACEHOLDER` 当 `VERIFIED` 用（要有判据）。
4. **真机验证仍是上线门槛**：demo 通过 ≠ 可上线。上线前必须完成 OP-76，此点写进发布清单。
5. **边界写进文档**：明确登记"哪些是合成的、合成了什么、上线前必须换成什么"。
