# M0 执行手册（可行性阶段 · W1–W2）

> 依据：研发执行计划 V2.0 §11「M0 启动清单」、文档 04 §4.1「M0：高风险前置」。
> 口径：M0 只回答"这条路走不走得通"，不产出业务功能。任何"M0 已实现八步"的说法都是越界。

## 1. M0 要回答的 5 个问题

| # | 问题 | 工作包 | 结论形态 |
|---|---|---|---|
| Q1 | 内网从零能跑起来吗（无公网依赖） | WP05 | 可运行环境 + 重启不丢数据证据 |
| Q2 | Live 图能不能真机发布 | WP02 | 可行链路 1 条 / 全不可行 + 替代决策 |
| Q3 | 数据字段到底能不能拿到 | WP03 | 逐字段「自动 / 导入 / 人工 / 不可得」清单 |
| Q4 | 模型质量够不够（含通过线数值） | WP04 | AQ-01~03 基线 + 运营负责人签字的通过线 |
| Q5 | 网络与出网策略允不允许模式 A | WP01 | 连通矩阵 + 白名单审批状态 |

## 2. 工作包与责任

| WP | 内容 | 执行方 | 可自动化 | 人日（计划） |

| WP01 | 服务器／网络清单、内部域名与 HTTPS、出网策略 | 运维/产品（**需企业 IT 配合**） | 部分（模板已备） | 2—3 |
| WP02 | Live 目标设备、配对样本、下载导入发布、批量交付 | AI/测试（**需真机**） | 否（协议已备） | 5—8 |
| WP03 | 笔记字段实测、后台样本、导入模板 | 后端B/产品（**需真实账号**） | 部分 | 2—4 |
| WP04 | 真实 Brief 评测集、候选模型、静态一致性评估 | AI/运营（**需真实 Brief**） | **是（工具链已交付）** | 6—8 |
| WP05 | 最小内网容器链、数据库与文件恢复小样 | 运维/后端A | **是（环境与冒烟脚本已交付）** | 6—10 |

**本机（开发机）已完成的部分**：

- WP05：`deploy/dev/docker-compose.yml` + `tools/m0/wp05_smoke/smoke.py` → 可立即验证"重启不丢文件与元数据"。
- WP04：`tools/m0/wp04_eval/score.py` + 评测集 Schema + 样例数据 → 可立即用于标注与打分。
- WP01/WP02/WP03：协议、模板、记录表已备齐 → 交企业侧/真机侧执行后回填。

**必须外部执行、无法替代的**：

- WP02 的**真机**验证（无 iPhone + 小红书账号 = 无法完成，不接受"文档推断可行"）。
- WP03 的**真实账号权限**验证（无账号 = 无法确认字段可得性）。
- WP01 的**企业网络现状**（无网管确认 = 无法确定出网与域名）。

## 4. G0 判定规则

- 五个问题**逐个**判定，不允许"总体感觉可以"。
- Q2（Live）与 Q4（模型质量）任一为"未通过"，不得宣布 M0 通过；可带条件推进 M1 基础工程，但 Live 与质量必须在大计划内保留独立关键路径（研发执行计划 §13 R2/R5）。
- 所有"待实测"项在 G0 前必须变成"已测通过 / 已测失败 / 未测（说明原因与计划）"三态之一，禁止继续挂"待验证"。
- **三态登记的唯一载体是 `docs/待定项与问题登记册.md`**（§2 的 OP 条目）。
  本手册与各工作包说明中的"待核实"清单均以该登记册为权威，只作指向，不再各自维护。
  G0 评审前必须复跑 `python tools/issues/log_issue.py --check` 并回填全部 OP 状态。

## 5. 禁止事项（M0 红线）

1. 不得用"文档说可行"替代真机实测（Live 尤其）。
2. 不得把公网可得数据推定为后台可得数据。
3. 不得为凑 G0 通过而虚报贯通率或质量分。
4. 不得在 M0 阶段开始业务功能开发（越界会导致 G0 判据失真）。
