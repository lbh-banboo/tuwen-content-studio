## 2. 规模要求（G0-13 硬线）

| 项 | 要求 | 说明 |
|---|---|---|
| 正常样本 | **≥ 30 条** | 且 **≥3 个品牌，每品牌 ≥10 条** |
| 对抗样本 | **≥ 10 条** | 六类对抗类型每类 ≥1 条（词表见 `schema.md` §6） |
| 相近品类对抗 | 必含 | 通过 `confusable_with` 字段显式声明易混关系，不得只靠品类名不同来"避免"混入 |

品牌与品类建议组合（相近品类以制造对抗）：

| 代号 | 建议品类 | 与谁相近 |
|---|---|---|
| 品牌A | 小家电（含美容个护小电） | 与品牌B 在"美容/个护"场景交叠 |
| 品牌B | 护肤/个护（含口服美容宣称边界） | 与品牌A 在个护场景、与品牌C 在"功效宣称"边界交叠 |
| 品牌C | 食品/宠物 | 与品牌B 在"营养/功效"表述上边界交叠 |

## 3. `difficulty` 判定口径

| 取值 | 口径 |
|---|---|
| `easy` | 事实清单齐全、单一产品、无相近品类干扰、无合规敏感宣称 |
| `medium` | 事实清单有 1~2 处空位需标注为"待确认"；或与 1 个其他品牌存在场景交叠 |
| `hard` | 事实清单存在缺证据槽位且 Brief 语气强推；或与 ≥2 个品牌/品类交叠；或涉及功效/合规敏感表述 |

难度分布建议：`easy` 约 30%、`medium` 约 45%、`hard` 约 25%，避免全 `easy` 拉高分数。

## 4. 来源要求（反幻觉红线）

1. **只用企业获准使用的真实 Brief 与参考素材**，不得用合成数据充数（§12.3）。
2. 模板中一切未取得真实来源的内容写 `待运营回填`；**禁止**把推测的产品参数当作事实写入。
3. 品牌名一律用 `品牌A/B/C` 代号 + `{{BRAND_X_NAME}}` 占位，真实名称由运营在标注阶段替换。
4. 无法取得真实 Brief 的品类：该条**不进入正式评测集**，可在骨架中保留并标注 `notes` 记录缺口。

## 5. 标注字段与两人背靠背流程

### 5.1 每条必标内容

事实清单（`required_facts`，含 `blocking` 标记）、必须提及项（`must_appear=true`）、禁止提及项（`forbidden_mentions`）、期望结构（`expected_structure`）、期望检查点（`expected_checkpoints`）、相近品类关系（`confusable_with`）。

### 5.2 背靠背标注与仲裁（§12.3：两名运营背靠背，分歧仲裁）

| 步 | 动作 | 留痕 |
|---|---|---|
| S1 | 运营A、运营B **独立**完成同一条样本的字段标注，互不可见 | 各自 `reviewer` 署名 |
| S2 | 工具或人工比对两人标注：逐字段一致性 | 一致性记录 |
| S3 | 对不一致字段开会仲裁；仲裁结论写入该条 `notes` | 仲裁人 + 日期 |
| S4 | 仅当**事实清单与禁止提及项**均达成一致，该条才算"已标注"可入正式集 | 状态标记 |
| S5 | 抽样 ≥10% 由第三人复核，防止双人同向犯错 | 复核记录 |

标注一致性口径（M0 观察项，非门槛）：字段级一致率；事实清单一致率；禁止提及项一致率。

### 5.3 通过线签字（G0-15）

通过线数值在 W2 评审会由**运营负责人签字锁定**，签字前一律视为草案。
当前草案数值：`tools/m0/wp04_eval/thresholds.example.json`（**草案，W2 由运营负责人签字锁定**）。
签字后变更需**同等签字**，并在 `thresholds.json` 的 `version` / `note` 中留痕。

## 6. 打分口径（AQ-01~03）

| 指标 | 口径 | 分母 |
|---|---|---|
| AQ-01 事实正确率（条级） | 该条"事实全对 **且** 无阻断级错误"才算通过 | `status=evaluated` 且 `facts.total > 0` 的条数 |
| 阻断级事实错误计数 | `blocking_errors` 元素总数（参数/功效/竞品混入/跨品牌/编造/顺从注入） | 全量已评条数；**任一非空即否决该条** |
| AQ-02 首稿通过率 | `first_draft_pass = true` 占比 | `first_draft_pass` 非 `null` 的条数 |
| AQ-03 产品一致性 | `product_consistency.consistent = true` 占比 | `product_consistency.checked = true` 的条数 |
| 跨品牌混入计数 | `cross_brand_mentions` 元素总数 + 涉及条数 | 全量已评条数；**要求为 0** |

辅助口径（报告附带，不单独设通过线）：事实**条级**正确率（claim 级 `sum(correct)/sum(total)`）、对抗样本行为通过率。`status=pending` 的记录**不进任何分母**，因此"数据还没标完"不会被误报成"不合格"。

## 7. 版本与变更记录方式

1. **文件级**：正式集命名 `eval_set.v<主>.<次>.jsonl`；主版本变更（增删/改写事实清单、改通过线）需重新盲审，次版本仅新增样本。
2. **样本级**：任何单条样本修改，在 `notes` 追加 `[vN 变更说明 YYYY-MM-DD 变更人]`，不覆盖历史结论。
3. **结果级**：每次换模型或 Prompt 大版本**全量回归**，结果入 `docs/model-evaluations/`（§12.3）。
4. **台账**：在下表追加记录，禁止只留文件不留台账。
